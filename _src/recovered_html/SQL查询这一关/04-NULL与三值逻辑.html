🎯 一句话

报表想找不在总部名单里的用户，查询却一行也没返回。先看名单里有没有 NULL，也就是 SQL 的缺值标记。普通等号遇到 NULL 会得到未知（UNKNOWN）。WHERE 只留下条件为真的行。

先回忆 01 章的查询顺序、02 章的连接和 03 章的分组。本章用小表定位缺值影响了哪一步，再用 05 章继续学习子查询。下面每段 Python 都能独立运行，使用标准库 sqlite3 和临时内存数据库，无需安装第三方库或准备数据文件。

⚠️ 零、先划清一件事：这不是「缺失值处理」

站内有一章叫《数据这一关》· 05 缺失不是一种东西，它讲的是统计学意义上的缺失：这个值为什么没有（MCAR / MAR / MNAR）、能不能填、填了会不会把偏差带进模型。

这一章讲的是完全不同的另一件事：值已经缺在库里了，NULL 这个东西在 SQL 里怎么参与运算和比较。

那一章问 这一章问
题目 这个值为什么没有？填成什么？ 已经是 NULL 了，WHERE／SUM／JOIN 会怎么对待它？
判据 缺失机制（MCAR/MAR/MNAR） 三值逻辑（TRUE/FALSE/UNKNOWN）
出错的样子 填错了，系数偏了 查询静默少了一批行，数据本身一个字没错

⚠️ 同名不同物，别混。 你可以在缺失机制上做得完全正确，仍然被本章这些坑打中——因为它们发生在你写 SQL 的那一刻，跟数据怎么来的没有半点关系。

⭐ 顺带一提，《数据这一关》· 04 脏数据的十种形态讲了一种更坏的东西：哨兵值（-999、"N/A"、1970-01-01）——只查 IS NULL 的缺失率监控会漏掉这些哨兵值。 相比之下 NULL 至少是诚实的：它明说自己不知道。本章讲的是这份诚实要你付出的代价。

🚦 一、招牌事故：一个 NULL 清空整个结果集

users 记录用户编号 id 和城市 city。hq 是总部城市名单，已录入北京（BJ），还有一行待补。试着找出未匹配到已录入城市的用户。

演示输入：用户城市
用户编号城市
1BJ
2SH
3NULL
4SH
5GZ
 
import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE users(id INTEGER PRIMARY KEY, city TEXT)")
db.executemany("INSERT INTO users VALUES(?,?)", [
    (1, "BJ"), (2, "SH"), (3, None), (4, "SH"), (5, "GZ"),
])
db.execute("CREATE TABLE hq(city TEXT)")
db.executemany("INSERT INTO hq VALUES(?)", [("BJ",), (None,)])   # ⭐ 混进了一行 NULL

print("NOT IN 字面量:",
      db.execute("SELECT id FROM users WHERE city NOT IN ('BJ', NULL)").fetchall())
print("NOT IN 子查询:",
      db.execute("SELECT id FROM users WHERE city NOT IN (SELECT city FROM hq)").fetchall())
print("NOT EXISTS:",
      db.execute("SELECT id FROM users u WHERE NOT EXISTS "
                 "(SELECT 1 FROM hq h WHERE h.city = u.city)").fetchall())
print("IN 子查询（对照）:",
      db.execute("SELECT id FROM users WHERE city IN (SELECT city FROM hq)").fetchall())

实跑输出：

NOT IN 字面量: []
NOT IN 子查询: []
NOT EXISTS: [(2,), (3,), (4,), (5,)]
IN 子查询（对照）: [(1,)]

结果中的 [(1,)] 表示一行，且这一行只有用户编号 1 这一列。没有 ORDER BY 的样例用来核对返回了哪些行，行的显示顺序随数据库执行而定。

程序先建两张小表。Python 的 None 写入 SQLite 后就是 NULL。两条 NOT IN 分别查写死的名单与子查询生成的名单，两边都是 ('BJ', NULL)，因此都返回 []（零行）。

IN 找到了唯一已确认匹配的用户 1。NOT EXISTS 返回 2、3、4、5，表示找不到城市相等的总部记录。用户 3 的城市还没录，是否应放进报表要单独决定。先学会算条件的真值，第四节再选查询写法。

🧩 二、三值逻辑：多出来的那个 UNKNOWN

系统只记录了用户 3 的编号。现在问“用户 3 的城市是 BJ 吗”，已有信息无法确定。NULL 标记缺少可用的值，具体原因由业务定义，可以是尚未录入或不适用。三值逻辑（Three-Valued Logic）给条件表达式三种结果：成立（TRUE）、不成立（FALSE）、无法判定（UNKNOWN）。例如 'BJ' = 'BJ' 为真，'SH' = 'BJ' 为假，NULL = 'BJ' 为未知。

设 A、B 是两个条件。AND 要求两者都成立，OR 要求至少一个成立，NOT 把真与假互换。如果已经有一个条件为假，AND 就是假；如果已经有一个条件为真，OR 就是真。 对未知取反仍是未知。表格中的 T、F、U 分别表示 TRUE、FALSE、UNKNOWN。

NOT T 得 F，NOT F 得 T，NOT U 得 U。例如条件 A 是“编号等于 3”，条件 B 是“城市等于 BJ”。用户 3 的 A 为 T、B 为 U，所以 A AND B 仍为 U，A OR B 已经为 T。这些规则描述最终真值。数据库何时求值属于执行细节。

运行下例时，q 把每个条件接在 SELECT 后，直接查看条件结果。SQLite 在这里返回 1、0 或 NULL，字典把 Python 收到的 1、0、None 换成三个真值的名字。

import sqlite3

db = sqlite3.connect(":memory:")

def q(sql):
    v = db.execute("SELECT " + sql).fetchone()[0]
    return {None: "UNKNOWN", 1: "TRUE", 0: "FALSE"}[v]

for e in ["NULL = NULL", "NULL <> NULL", "NULL > 1", "NULL = 0",
          "NULL IS NULL", "NULL IS NOT NULL"]:
    print(f"{e:<18} -> {q(e)}")

print("--- AND / OR / NOT ---")
for a in ["1", "0", "NULL"]:
    for b in ["1", "0", "NULL"]:
        print(f"{a:>4} AND {b:<5} -> {q(f'{a} AND {b}'):<8}"
              f"{a:>4} OR {b:<5} -> {q(f'{a} OR {b}')}")
for a in ["1", "0", "NULL"]:
    print(f"NOT {a:<5} -> {q('NOT ' + a)}")

回到用户名单。对单列列表，city IN ('BJ', NULL) 相当于 city = 'BJ' OR city = NULL，外面加 NOT 就得到 NOT IN 的真值。先算两次比较，再算 OR，最后取反。

用户 1 的 TRUE OR UNKNOWN 为 TRUE，取反得到 FALSE。用户 2 的 FALSE OR UNKNOWN 为 UNKNOWN，取反后仍然未知。五行里没有一行的 NOT IN 为真，所以它单独作为 WHERE 条件时返回零行。这个推导适用于右侧含 NULL 的标量（单列）NOT IN。

SQLite 中 1 + NULL、0 * NULL、'abc' || NULL、length(NULL) 和 upper(NULL) 都返回 NULL。聚合函数和其他数据库的字符串函数需要按各自规则判断。

🧯 三、WHERE 筛行、ON 配对、HAVING 筛组

WHERE 逐行判断，只保留条件为 TRUE 的行。假设 v 是订单金额，单位为元，报表要找超过 10 元的订单。金额待补的订单在原条件与取反条件下都得不到确定的答案。

同一行在四个条件下的真值
编号与金额v > 10NOT (v > 10)v = NULLv IS NULL
1 · 5 元FTUF
2 · NULLUUUT
3 · 20 元TFUF
 
import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE t(id INTEGER PRIMARY KEY, v INTEGER)")
db.executemany("INSERT INTO t VALUES(?,?)", [(1, 5), (2, None), (3, 20)])

a = db.execute("SELECT id FROM t WHERE v > 10").fetchall()
b = db.execute("SELECT id FROM t WHERE NOT (v > 10)").fetchall()
print("WHERE v > 10       :", a)
print("WHERE NOT (v > 10) :", b)
print("两边相加:", len(a) + len(b), "行 / 全表 3 行")
print("WHERE v > 10 OR NOT (v > 10):",
      db.execute("SELECT id FROM t WHERE v > 10 OR NOT (v > 10)").fetchall())
print("= NULL 写法 :", db.execute("SELECT id FROM t WHERE v = NULL").fetchall())
print("IS NULL 写法:", db.execute("SELECT id FROM t WHERE v IS NULL").fetchall())

实跑输出：

WHERE v > 10       : [(3,)]
WHERE NOT (v > 10) : [(1,)]
两边相加: 2 行 / 全表 3 行
WHERE v > 10 OR NOT (v > 10): [(1,), (3,)]
= NULL 写法 : []
IS NULL 写法: [(2,)]

💀💀 一个条件和它的否定，加起来不等于全表。 3 行的表，两边各拿走 1 行，有 1 行谁都没要。 连 WHERE v > 10 OR NOT (v > 10) 这种看上去必然恒真的条件，都漏掉了 id=2。

⚠️ 这条在业务上非常贵：「大额订单」和「非大额订单」两张报表加起来对不上总数，两边的 SQL 都是对的，两边的开发都查不出问题。

如果报表要求覆盖全表，可以把“金额待补”单独列一组；如果报表明确把待补订单计入第二组，就写 WHERE NOT (v > 10) OR v IS NULL。给待补记录选择分组时，要依据报表口径。

IS NULL 为什么不能写成 = NULL

v = NULL 用普通等号比较，右侧始终缺值，因此每行都得到 UNKNOWN。v IS NULL 检查标量 v 是否带有缺值标记，结果只有真或假，只有编号 2 为真。IS NOT NULL 检查是否有值，保留编号 1、3。

ON 决定配对，HAVING 决定留组

沿用 20 元、5 元、金额待补三种情况。账户表 accounts 有编号 1、2、3，付款表 payments 各有一笔付款，付款编号分别为 11、22、33。按账户编号相等找候选配对。每个账户只有一个编号相等的候选，其余候选因编号不等而无法通过 AND。

ON 的整个条件为真时才建立配对。用 LEFT JOIN 时，没有任何配对的左行仍保留，右侧列由连接补为 NULL。把金额条件写到 WHERE，则在连接之后检查每一行，金额为 NULL 的行会被排除。

把金额门槛放到 ON 与 HAVING 后
账户付款金额ON 配对LEFT JOIN 的付款编号HAVING 留组
120 元T11T
25 元FNULLF
3NULLUNULLU

用原始付款表按账户分组。SUM(amount) 对非 NULL 金额求和。三组的合计分别是 20、5、NULL，因为第三组没有可加的数。HAVING SUM(amount) > 10 只让账户 1 的组通过。这里的 HAVING 与 WHERE 使用相同的真值门槛，判断的单位分别是组和行。

import sqlite3

db = sqlite3.connect(":memory:")
db.executescript("""
CREATE TABLE accounts(id INTEGER PRIMARY KEY);
INSERT INTO accounts VALUES (1), (2), (3);
CREATE TABLE payments(id INTEGER PRIMARY KEY, account_id INTEGER, amount INTEGER);
INSERT INTO payments VALUES (11, 1, 20), (22, 2, 5), (33, 3, NULL);
""")

join = """SELECT a.id, p.id
FROM accounts a LEFT JOIN payments p ON p.account_id = a.id"""
print("ON 筛配对:", db.execute(join + " AND p.amount > 10 ORDER BY a.id").fetchall())
print("WHERE 筛行:", db.execute(join + " WHERE p.amount > 10 ORDER BY a.id").fetchall())

groups = "SELECT account_id, SUM(amount) FROM payments GROUP BY account_id"
print("所有组:", db.execute(groups + " ORDER BY account_id").fetchall())
print("HAVING 筛组:", db.execute(groups + " HAVING SUM(amount) > 10 ORDER BY account_id").fetchall())

运行结果（Python 用 None 显示 SQL 的 NULL）。

ON 筛配对: [(1, 11), (2, None), (3, None)]
WHERE 筛行: [(1, 11)]
所有组: [(1, 20), (2, 5), (3, None)]
HAVING 筛组: [(1, 20)]

前两行结果中的每对数字依次是账户编号、付款编号。后两行的第二列是组内金额合计。账户 3 的付款 33 确实存在，但 ON 里的金额条件为未知，输出中的右侧编号因此是补出来的 NULL。

⚠️ 一个反直觉的例外：CHECK 约束放行 UNKNOWN

CHECK 是写入数据时检查的约束。用年龄演示三种情况：30 岁通过，10 岁判为假而被拒，年龄待补时条件为未知。

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE c(id INTEGER, age INTEGER CHECK (age >= 18))")
db.execute("INSERT INTO c VALUES(1, 30)")
for label, age in [("age=10", 10), ("age=NULL", None)]:
    try:
        db.execute("INSERT INTO c VALUES(?,?)", (99, age))
        print(f"  {label:<9} 插入成功")
    except Exception as e:
        print(f"  {label:<9} ->", type(e).__name__, ":", e)
print("  表里最终:", db.execute("SELECT id, age FROM c").fetchall())

实跑输出：

  age=10    -> IntegrityError : CHECK constraint failed: age >= 18
  age=NULL  插入成功
  表里最终: [(1, 30), (99, None)]

⭐ CHECK 的规则是「只在判为 FALSE 时拒绝」——UNKNOWN 放行。 💀 所以 CHECK (age >= 18) 挡不住 NULL。要真的挡住，得写 CHECK (age IS NOT NULL AND age >= 18)，或者给列加 NOT NULL。

按使用位置判断结果：WHERE 与 HAVING 要求真才保留行或组，ON 要求真才配对，CHECK 遇到假才拒绝写入。

🩹 四、反连接：找不到匹配行时留谁

找左表中没有匹配右行的记录，称为反连接（anti-join）。沿用第一节的 users 与 hq。先明确报表要找“没有查到匹配记录”的用户，还是只统计城市已知的用户。运行下面四种写法，观察缺城市的用户 3 去了哪里。

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE users(id INTEGER PRIMARY KEY, city TEXT)")
db.executemany("INSERT INTO users VALUES(?,?)", [
    (1, "BJ"), (2, "SH"), (3, None), (4, "SH"), (5, "GZ")])
db.execute("CREATE TABLE hq(city TEXT)")
db.executemany("INSERT INTO hq VALUES(?)", [("BJ",), (None,)])

print("A. NOT IN            :",
      db.execute("SELECT id FROM users WHERE city NOT IN (SELECT city FROM hq)").fetchall())
print("B. NOT EXISTS        :",
      db.execute("SELECT id FROM users u WHERE NOT EXISTS "
                 "(SELECT 1 FROM hq h WHERE h.city = u.city)").fetchall())
print("C. LEFT JOIN IS NULL :",
      db.execute("SELECT u.id FROM users u LEFT JOIN hq h ON h.city = u.city "
                 "WHERE h.city IS NULL").fetchall())
print("D. NOT IN + 内层过滤  :",
      db.execute("SELECT id FROM users WHERE city NOT IN "
                 "(SELECT city FROM hq WHERE city IS NOT NULL)").fetchall())
print("--- 子查询为空表时 ---")
db.execute("CREATE TABLE empty_hq(city TEXT)")
print("NOT IN 空表:",
      db.execute("SELECT id FROM users WHERE city NOT IN (SELECT city FROM empty_hq)").fetchall())
print("B + 外层只留已知城市:", db.execute(
    "SELECT u.id FROM users u WHERE u.city IS NOT NULL AND NOT EXISTS "
    "(SELECT 1 FROM hq h WHERE h.city = u.city) ORDER BY u.id"
).fetchall())

实跑输出：

A. NOT IN            : []
B. NOT EXISTS        : [(2,), (3,), (4,), (5,)]
C. LEFT JOIN IS NULL : [(2,), (3,), (4,), (5,)]
D. NOT IN + 内层过滤  : [(2,), (4,), (5,)]
--- 子查询为空表时 ---
NOT IN 空表: [(1,), (2,), (3,), (4,), (5,)]
B + 外层只留已知城市: [(2,), (4,), (5,)]

三种写法 + 一个补救版，跑出三个不同答案。 逐个解释：

写法 结果 发生了什么
A NOT IN 空 💀 已匹配 BJ 的用户 1 判为 FALSE，其余四行判为 UNKNOWN
B NOT EXISTS 4 行 子查询的 WHERE h.city = u.city 只保留真匹配。用户 1 找到一行，其他四位找到零行。EXISTS 检查是否至少有一行，NOT EXISTS 在零行时为真。
C LEFT JOIN … IS NULL 4 行 与 B 相同。这里用普通等号比较城市，任何真匹配的右侧 h.city 都有值。一般可检查右表声明为 NOT NULL 的标识列，避免把已匹配但该列缺值的行误当成未匹配。
D NOT IN + 内层滤掉 NULL 3 行 内层干净了，但 ⚠️ 外层的 id=3 自己是 NULL，NULL NOT IN ('BJ') 仍是 UNKNOWN，被扔了

h 和 u 是两张表的别名。内层条件引用当前外行的 u.city，这叫相关子查询。SELECT 1 对每条满足条件的右行返回一个占位值，EXISTS 只看是否有行。用户 3 的 NULL 与 'BJ'、NULL 的普通等号比较都是未知，内层返回零行，所以 B 会留下用户 3。

如果口径要求城市已知且没有匹配，给 B 加上外层条件 u.city IS NOT NULL AND NOT EXISTS (...)。若采用 D，内层过滤只处理右侧的缺值，仍可显式加 city IS NOT NULL 控制左侧。

右侧子查询返回零行时，IN 为假、NOT IN 为真，即使左值是 NULL。所以 D 过滤完右表之后若得到空结果，仍可能保留用户 3。示例用空子查询演示这一点。SQLite 也接受空的字面量列表 IN ()，很多数据库要求列表至少有一项。

无论右侧来自字面量还是子查询，都要检查两侧可空性。右侧已知且非空时，左侧缺值仍会使普通 NOT IN 为未知。SQLite 的 IN / NOT IN 结果表 · PostgreSQL 子查询条件

🧮 五、那些 NULL 行，到底是在哪一步没的

延续 03 章的聚合。先看三笔付款（20 元、5 元、金额待补）都进入同一个总计。COUNT(*) 数输入行，所以是 3。COUNT(amount) 数金额非 NULL 的行，所以是 2。两数相减 3 − 2 = 1，说明还有一笔金额没录。金额为 0 也会进入 COUNT(amount)。

这三笔的已知金额和是 20 + 5 = 25 元，AVG(amount) 用 2 作分母，得到 25 ÷ 2 = 12.5 元。若报表只剩一笔待补记录，行数是 1，已知金额数是 0。再把它筛掉，两个计数才都为 0。这两种情况下 SUM 和 AVG 都返回 NULL。下面使用无 GROUP BY 的汇总，空输入也返回一行结果。

import sqlite3

db = sqlite3.connect(":memory:")
db.executescript("""
CREATE TABLE payments(id INTEGER PRIMARY KEY, amount INTEGER);
INSERT INTO payments VALUES (11, 20), (22, 5), (33, NULL);
""")

summary = "SELECT COUNT(*), COUNT(amount), SUM(amount), AVG(amount) FROM payments"
print("全部:", db.execute(summary).fetchone())
print("仅待补:", db.execute(summary + " WHERE id = 33").fetchone())
print("零输入行:", db.execute(summary + " WHERE id = 99").fetchone())

在本例中，SUM、AVG、MIN 和 MAX 都只使用非 NULL 的金额。聚合的返回类型和空输入规则要查具体函数。例如 SQLite 的 AVG 对整数输入仍返回浮点数，SQL Server 的 AVG(int) 返回整数，需小数时可以先转换输入类型。SQLite 的 total 在没有非空值时返回 0.0，PostgreSQL 的 array_agg 则可把输入的 NULL 收进数组。SQLite 聚合函数 · PostgreSQL 聚合函数 · SQL Server AVG

接下来区分另一种情况：通话的金额已录入，但城市缺失。以下金额沿用示例表的 cents，单位为分。先算全表的 1 + 2 + 4 + 8 + 16 = 31，再核对每种查询让哪些行参与求和。

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE calls(id INTEGER PRIMARY KEY, city TEXT, cents REAL)")
db.executemany("INSERT INTO calls VALUES(?,?,?)", [
    (1, "BJ", 1.0), (2, "SH", 2.0), (3, None, 4.0), (4, "BJ", 8.0), (5, None, 16.0)])
db.execute("CREATE TABLE dim_city(code TEXT, name TEXT)")
db.executemany("INSERT INTO dim_city VALUES(?,?)", [("BJ", "北京"), ("SH", "上海")])

print("全表 SUM =", db.execute("SELECT SUM(cents) FROM calls").fetchone()[0])
print("GROUP BY :", db.execute("SELECT city, SUM(cents) FROM calls GROUP BY city").fetchall())
print("--- 换成下面任意一步，NULL 那 20.0 就没了（都不报错）---")
print("a) INNER JOIN 维表    :",
      db.execute("SELECT SUM(c.cents) FROM calls c JOIN dim_city d ON d.code=c.city").fetchone()[0])
print("b) WHERE city <> 'BJ' :",
      db.execute("SELECT SUM(cents) FROM calls WHERE city <> 'BJ'").fetchone()[0],
      "  <- 期望 2+4+16=22")
print("c) WHERE city IN (…)  :",
      db.execute("SELECT SUM(cents) FROM calls WHERE city IN ('BJ','SH')").fetchone()[0])
print("b 补上 NULL 之后      :",
      db.execute("SELECT SUM(cents) FROM calls WHERE city IS NULL OR city <> 'BJ'").fetchone()[0])

实跑输出：

全表 SUM = 31.0
GROUP BY : [(None, 20.0), ('BJ', 9.0), ('SH', 2.0)]
--- 换成下面任意一步，NULL 那 20.0 就没了（都不报错）---
a) INNER JOIN 维表    : 11.0
b) WHERE city <> 'BJ' : 2.0   <- 期望 2+4+16=22
c) WHERE city IN (…)  : 11.0
b 补上 NULL 之后      : 22.0

⭐ GROUP BY 一分钱没丢：三组加起来正好 31.0，NULL 老老实实自成一组，占 20.0——接近全表的三分之二。 （GROUP BY 把所有 NULL 收进同一组，用的是本章第六节要讲的「另一套语义」。）

💀 丢在后面三步，而且都不报错：

那一步 结果 为什么
a 连维表（INNER JOIN） 31.0 → 11.0 连接键 NULL 配不上对（02 章第六节），那两行被内连接扔了
b WHERE city <> 'BJ' 应是 22.0，实得 2.0 ⚠️ NULL <> 'BJ' 判 UNKNOWN，WHERE 不放行——一个「不等于」吞掉 20.0
c WHERE city IN (…) 11.0 对城市缺值的两行，IN ('BJ','SH') 为 UNKNOWN，WHERE 排除它们。

⚠️ b 这一格最值得盯：写的人想表达「除了北京的都算上」，实际算出来的是「城市已知且不是北京的」——少了 20.0，占全表 64.5%。 补一句 city IS NULL OR 就回到 22.0。

上表中的三种查询各自从原表开始。GROUP BY 之后未知城市组的两行仍然贡献 4 + 16 = 20 分。左连接后的报表也可以同时保留两个计数：COUNT(*) 数结果行（包括补行），COUNT(右表标识列) 数实际匹配行，前提是该标识在右表中必有值。

🔀 六、⭐ SQL 里其实有两套 NULL 语义

比较条件、分组、去重和排序有各自的规则。下例用两个城市缺值的用户观察分组与去重，再用邮箱演示 SQLite 的唯一约束。输出中没有指定排序的查询，只比较结果内容。

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE u(id INTEGER PRIMARY KEY, city TEXT)")
db.executemany("INSERT INTO u VALUES(?,?)", [(1, "BJ"), (2, None), (3, None), (4, "SH")])

print("GROUP BY :", db.execute("SELECT city, COUNT(*) FROM u GROUP BY city").fetchall())
print("DISTINCT :", db.execute("SELECT DISTINCT city FROM u").fetchall())
print("UNION    :", db.execute("SELECT city FROM u UNION SELECT city FROM u").fetchall())
print("NULL IS NULL / 1 IS NULL:", db.execute("SELECT (NULL IS NULL), (1 IS NULL)").fetchone())

db.execute("CREATE TABLE uq(id INTEGER PRIMARY KEY, email TEXT UNIQUE)")
db.execute("INSERT INTO uq VALUES(1, 'a@x.com')")
try:
    db.execute("INSERT INTO uq VALUES(2, 'a@x.com')")
except Exception as ex:
    print("重复字符串 ->", type(ex).__name__, ":", ex)
db.executemany("INSERT INTO uq VALUES(?,?)", [(3, None), (4, None), (5, None)])
print("UNIQUE 列里的三个 NULL:", db.execute("SELECT id, email FROM uq").fetchall())

需要让两个缺值在连接中匹配时，要显式使用支持空值的相等判断。对普通标量列，SQLite 可写 a IS b，PostgreSQL 可写 a IS NOT DISTINCT FROM b，MySQL 提供 a <=> b。如果两边有多行缺值，缺值之间也会组合出多对。SQLite 表达式 · PostgreSQL 比较谓词 · MySQL 比较运算符

唯一约束按数据库自身规则检查。SQLite 的例子拒绝重复的 'a@x.com'，接受三个 NULL。如果业务要求邮箱必填且唯一，就同时声明 NOT NULL 和 UNIQUE。PostgreSQL 15 起也可声明 UNIQUE NULLS NOT DISTINCT，让单列唯一约束最多接受一个缺值。PostgreSQL 15 唯一约束

ORDER BY 里 NULL 排哪儿

五行的排序键 v 分别是 30、NULL、10、NULL、20。先预测升序的第一行，再从已知数字 30、10、20 中找出最小值。下面的默认排序样例展示 SQLite 的结果，v 相同时需要第二排序键才能指定先后。

import sqlite3

print("sqlite version:", sqlite3.sqlite_version)
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE t(id INTEGER PRIMARY KEY, v INTEGER)")
db.executemany("INSERT INTO t VALUES(?,?)", [(1, 30), (2, None), (3, 10), (4, None), (5, 20)])

print("ORDER BY v          :", db.execute("SELECT id, v FROM t ORDER BY v").fetchall())
print("ORDER BY v DESC     :", db.execute("SELECT id, v FROM t ORDER BY v DESC").fetchall())
print("ORDER BY (v IS NULL), v :",
      db.execute("SELECT id, v FROM t ORDER BY (v IS NULL), v").fetchall())
print("MIN(v)              =", db.execute("SELECT MIN(v) FROM t").fetchone()[0])
print("ORDER BY v LIMIT 1  =", db.execute("SELECT v FROM t ORDER BY v LIMIT 1").fetchone()[0])
order = "CASE WHEN v IS NULL THEN 1 ELSE 0 END, v, id"
print("CASE 指定缺值在末尾:", db.execute("SELECT id, v FROM t ORDER BY " + order).fetchall())

实跑输出（SQLite 3.50.4）：

sqlite version: 3.50.4
ORDER BY v          : [(2, None), (4, None), (3, 10), (5, 20), (1, 30)]
ORDER BY v DESC     : [(1, 30), (5, 20), (3, 10), (2, None), (4, None)]
ORDER BY (v IS NULL), v : [(3, 10), (5, 20), (1, 30), (2, None), (4, None)]
MIN(v)              = 10
ORDER BY v LIMIT 1  = None
CASE 指定缺值在末尾: [(3, 10), (5, 20), (1, 30), (2, None), (4, None)]

💀 MIN(v) 是 10，ORDER BY v LIMIT 1 是 NULL。 两句在英语里都念作「最小的那个」，SQLite 上给出不同答案——因为 MIN 跳过 NULL（聚合的规则，03 章），而 ORDER BY 把它排在最前（排序的规则，上面那张表）。⭐ 同一个 NULL，两套语义，两个答案。

库 ORDER BY x ASC 里 NULL 在 支持 NULLS FIRST/LAST 验证情况
SQLite 最前（视为最小） ✅ 3.30+ ⭐ 实跑于 3.50.4
PostgreSQL 最后（视为最大） ✅ 🗓️ 未实跑
MySQL 8.4 最前 无此语法 官方文档，未实跑
SQL Server最前无此语法官方文档，未实跑

这四种数据库的默认降序位置与升序相反。按更新时间降序取第一行时，SQLite 会先给出已知时间，PostgreSQL 默认可能先给出缺值行。SQLite 3.30 起及 PostgreSQL 可写 ORDER BY v ASC NULLS LAST, id。

跨这四种数据库可以写 ORDER BY CASE WHEN v IS NULL THEN 1 ELSE 0 END, v, id。先按第一个排序键升序，非空行得到 0，缺值行得到 1。再按 v 升序排已知数，最后用 id 给并列行定序。本例的编号顺序是 3、5、1、2、4。原示例的 (v IS NULL) 排序键适用于 SQLite、PostgreSQL 和 MySQL。SQLite 排序 · PostgreSQL 排序 · MySQL 8.4 缺值 · SQL Server 排序

🧰 七、日常工具：COALESCE / NULLIF / 空串不是 NULL

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE p(id INTEGER PRIMARY KEY, nick TEXT, name TEXT, note TEXT)")
db.executemany("INSERT INTO p VALUES(?,?,?,?)", [
    (1, "小明", "王明", "hi"),
    (2, None,   "李雷", ""),      # note 是空串
    (3, "",     "韩梅", None),    # nick 是空串
    (4, None,   None,   None),
])
print("COALESCE          :", db.execute("SELECT id, COALESCE(nick, name, '(匿名)') FROM p").fetchall())
print("套一层 NULLIF     :",
      db.execute("SELECT id, COALESCE(NULLIF(nick,''), name, '(匿名)') FROM p").fetchall())
print("note = ''         :", db.execute("SELECT id FROM p WHERE note = ''").fetchall())
print("note IS NULL      :", db.execute("SELECT id FROM p WHERE note IS NULL").fetchall())
print("COUNT(note)       :", db.execute("SELECT COUNT(note) FROM p").fetchone()[0])
print("length('') / length(NULL):", db.execute("SELECT length(''), length(NULL)").fetchone())
print("拼接被吞          :", db.execute("SELECT id, '你好, ' || nick FROM p").fetchall())
print("NULLIF 防除零     :", db.execute("SELECT NULLIF(5,5), 10 / NULLIF(0,0)").fetchone())

实跑输出：

COALESCE          : [(1, '小明'), (2, '李雷'), (3, ''), (4, '(匿名)')]
套一层 NULLIF     : [(1, '小明'), (2, '李雷'), (3, '韩梅'), (4, '(匿名)')]
note = ''         : [(2,)]
note IS NULL      : [(3,), (4,)]
COUNT(note)       : 2
length('') / length(NULL): (0, None)
拼接被吞          : [(1, '你好, 小明'), (2, None), (3, '你好, '), (4, None)]
NULLIF 防除零     : (None, None)

⚠️ 先看「拼接被吞」那行：id=2 和 id=4 的 nick 是 NULL，'你好, ' || NULL 整体变成 NULL（第二节那条「字符串也被吞」）——你想拼一句问候语，拿到的是一个空值。 而 id=3 的 nick 是空串，拼出来是 '你好, '：不是 NULL，只是少了个名字。⭐ 这一行输出里同时藏着本节要讲的两件事。

函数 做什么 典型用途
COALESCE(a, b, c) 返回第一个非 NULL 的参数 兜底默认值；⭐ 三个库通用，优先于 SQLite 的 IFNULL / MySQL 的 IFNULL / Oracle 的 NVL
NULLIF(a, b) a = b 时返回 NULL，否则返回 a ⭐ 防除零（x / NULLIF(y, 0)）；把哨兵值转回 NULL（NULLIF(age, -999)）

💀 空串 '' 不是 NULL，它是一个长度为 0 的真实字符串。 实跑三处都在证明这件事： note IS NULL 只找到 id=3,4，note = '' 找到的是 id=2；COUNT(note) 是 2（空串被数进去了）；length('') 是 0 而 length(NULL) 是 NULL。

⚠️ 所以 COALESCE(nick, name, '(匿名)') 对 id=3 返回空串——它的 nick 是空串不是 NULL，COALESCE 认这个值。 ⭐ 修法是套一层 NULLIF：COALESCE(NULLIF(nick,''), name, '(匿名)')，实跑正确返回 韩梅。

⭐ 判据：在写入端就定一个规矩——一列里要么统一存 NULL，要么统一存空串，别两种都有。 一个前端没填就提交空串的表单，会让表里同时存在两种「没有」，而所有 IS NULL 检查只看得见其中一种。 （🗓️ 未实跑：Oracle Database 会把零长度字符值视为 NULL。Oracle 19c 缺值规则）

👀 答案
  1. 《数据这一关》研究缺失的原因以及填补对分析的影响。本章研究值存为 NULL 后查询怎样计算。
  2. 依次是 UNKNOWN、TRUE、UNKNOWN。一项为假足以使 AND 为假，一项为真足以使 OR 为真。
  3. BJ 的 IN 为真，取反为假。SH 与 NULL 的 IN 都是未知，取反仍是未知。只有 BJ 通过 IN。
  4. 第三笔比较为未知，无法通过 WHERE。在 ON 中它无法配对，左连接保留账户 3 并把付款编号补为 NULL。从原付款分组时，账户 3 的合计为 NULL，账户 2 的合计 5 小于门槛，只有账户 1 的 20 通过 HAVING。
  5. 接受。CHECK 在条件为假时拒绝，可以同时用 NOT NULL 要求该列有值。
  6. A、B、C、D 依次是 0、4、4、3 行。给 B 加外层 u.city IS NOT NULL。右侧子查询返回零行时，即使左侧城市缺值，NOT IN 也为真。

  8. 分到同组。普通等值连接的配对条件为未知，无法匹配。MIN(v) 在 30、10、20 中取 10，SQLite 默认升序把缺值放在最前。可用 CASE WHEN v IS NULL THEN 1 ELSE 0 END 作第一个排序键，把缺值排在末尾。
  9. 在 SQLite 中得到空串。可用 COALESCE(NULLIF(nick, ''), name, '(匿名)') 先把空串转为 NULL，再找第一个有值的参数。

🛑 可以停在这里

  • 用 IS NULL 检查缺值。用普通比较算条件时，先写出 TRUE、FALSE 或 UNKNOWN，再做 AND、OR 和 NOT。
  • WHERE 留真行，HAVING 留真组，ON 配对需要真。左连接会为没有配对的左行补出空的右侧列。
  • 反连接先确定外侧缺值如何处理。NOT EXISTS 检查有没有真匹配。含缺值的单列 NOT IN 右侧会让未匹配行的条件变为未知。
  • 核对 COUNT(*) 和 COUNT(列)，分别检查输入行数与已知值数。取排序首行时，显式指定缺值位置和并列顺序。
