C05 · 不泄漏的预处理 Pipeline：从原始数据到可信预测

⏱ 阅读约 23 分钟 · 动手练习另计

模型没有偷看“是否超时”，只是先把全部数据标准化了一遍——为什么评估仍可能是假的？

因为标准化、填补缺失值、类别编码和特征选择都可能从数据中学到信息。验证集不是禁止被预测，而是不能参与训练阶段的参数估计和模型选择；我们要把整套预处理放进一个可重复执行的流程。

学完能区分 fit 与 transform，手算一次训练集的填补和标准化，解释 ColumnTransformer / Pipeline 的工作方式，并识别交叉验证中的预处理泄漏。

前置：A04 · 数据与划分、05 · 泛化与交叉验证 和 16 · 特征工程。本课是对它们的实践衔接，不是替代。接下来：D01 · KNN模型，学习如何在相同验证协议下比较算法。

一、先把问题、字段与划分写明白

假设我们在下单时预测订单是否会超过 30 分钟。候选特征有“距离（公里）”和“当前天气”；标签是送达后观察到的“是否超时”。以下六单是人为构造的演示数据，按发生时间从早到晚排列，数据量太小，不可据此推断实际预测效果。

订单距离 km当前天气是否超时 y数据组
12晴0训练
24雨1训练
3缺失晴0训练
46雨1训练
58雪1验证
610雨1验证

这次按时间顺序用前四条训练，后两条验证；验证集的信息不能参与预处理的参数拟合。在其他任务里，可以使用分层、分组或时间序列划分，但必须先根据任务决定划分规则。

二、填补缺失值时也有“学到的参数”

第 3 单距离缺失。我们使用中位数填补：先把训练集里已知的三个距离排成 [2,4,6]，中间的数为 4 公里，因此缺失值填成 4。此时训练距离变成 [2,4,4,6]。

错误做法：先把验证集的 8、10 公里也加进来。所有已知距离会变成 [2,4,6,8,10]，中位数变成 6。这样训练样本第 3 单就被填成 6 而不是 4。虽然没读验证标签，还是利用了未来验证数据的统计信息。

训练数据一旦计算出填充值，这个值就必须保留下来，在验证和上线推理时重复使用。fit 就是“从训练数据估计这些参数”，transform 是“使用已经确定的参数转换新数据”。

三、标准化要接在填补之后

标准化使用公式 z=(x−μ)/σ，其中 x 是某一订单距离，μ 是填补后训练集的平均距离，σ 是该训练集的总体标准差，z 表示距离均值几个标准差（没有公里单位）。

  1. 训练距离已填补为 [2,4,4,6] 公里。
  2. 均值：μ=(2+4+4+6)/4=4 公里。
  3. 方差：σ²=[(2−4)²+(4−4)²+(4−4)²+(6−4)²]/4=(4+0+0+4)/4=2 平方公里。
  4. 标准差：σ=√2≈1.414 公里。
  5. 第 5 单距离 8 公里，验证时复用训练参数：z=(8−4)/√2≈2.828。

注意：验证订单离训练均值很远，标准化结果超过 2 是合理现象，不应该为了把它压回某个范围而重算均值和标准差。如果训练数据这一列恒定，σ=0，需要转换器妥善处理，不能直接除零。

四、实验：同一单 8 公里，为什么会有两个不同的标准化结果

切换下面的方案，观察填补值和统计参数的变化。错误方案不是建议做法，只用于识别数据泄漏。

缺失距离填补中位数4 km
均值 μ4 km
标准差 σ1.414 km
8 km 验证单的 z 值2.828

正确方案：只在训练数据上拟合预处理参数，验证数据仅 transform。8 公里被转换为 2.828。

若选中错误方案，合并六单后填补中位数为 6，距离序列为 [2,4,6,6,8,10]，均值 μ=6，方差 σ²=40/6≈6.667，标准差约 2.582；同一张 8 公里订单被变换成 (8−6)/2.582≈0.775。这不是“更聪明的标准化”，而是提前窥见了验证集的分布信息。

五、距离是数字，天气是类别，不能混成同一种运算

训练集的天气只有“晴”和“雨”；如果直接把“晴=0，雨=1”，线性模型可能把编码误读成大小或距离关系。常见做法是独热编码（One-Hot）：为训练时见过的每种类别建立指示列。

当前天气训练期“晴”指示列训练期“雨”指示列
晴10
雨01
雪（验证期新类别）00

表中“雪”变为全零，是采用 handle_unknown="ignore" 的行为。这能让推理不中断，但不意味着雪就是晴天或没有影响；模型无法从训练期未见过的类别学到可靠规律。真实系统需考虑未知类别的监控与处理策略。

六、Pipeline 把整个处理流程锁在正确顺序里

如果手工先在全数据上调用 fit_transform，再做交叉验证，预处理的均值、填充值、类别字典等就可能已经“见过”验证折的数据。正确顺序是：先划分，再在训练折 fit 预处理及模型，在验证折仅 transform 和 predict。

七、用 sklearn 的 Pipeline 和 ColumnTransformer 运行

import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

data = pd.DataFrame({
    "距离公里": [2, 4, None, 6, 8, 10],
    "当前天气": ["晴", "雨", "晴", "雨", "雪", "雨"],
    "是否超时": [0, 1, 0, 1, 1, 1],
})
features = ["距离公里", "当前天气"]
X_train, y_train = data.loc[:3, features], data.loc[:3, "是否超时"]
X_valid, y_valid = data.loc[4:, features], data.loc[4:, "是否超时"]

num_steps = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])
preprocess = ColumnTransformer([
    ("num", num_steps, ["距离公里"]),
    ("weather", OneHotEncoder(handle_unknown="ignore"), ["当前天气"]),
])
model = Pipeline([
    ("preprocess", preprocess),
    ("classifier", LogisticRegression(max_iter=1000)),
])
model.fit(X_train, y_train)  # 只有前四单参与 fit
numeric = model.named_steps["preprocess"].named_transformers_["num"]
print(numeric.named_steps["impute"].statistics_[0])  # 4.0
print(round(numeric.named_steps["scale"].mean_[0], 3))  # 4.0
print(model.predict_proba(X_valid)[:, 1])  # 两张验证单的概率；不是上线效果

代码里的 ColumnTransformer 是“不同列使用不同处理器”；Pipeline 是“串联多个步骤”。不应拿最后两条样本选择最佳参数之后，再用这两个样本宣称一次独立测试成绩。

注意：这里是极小的时间顺序示例，不适合用交叉验证表现来评价真实模型。在足够数据且分组/时间规则允许时，交叉验证应该把完整 Pipeline 作为每折重新拟合的对象，而不是先对全量数据做完预处理。

八、检查点：自己能解释这三个问题吗

  1. 把两条验证订单加进来求填补中位数，为什么会使训练流程泄漏信息？
  2. 正确流程中，8 公里订单标准化后的数是约 2.828 还是 0.775？
  3. 如果验证集突然出现训练期没见过的天气“雪”，编码器该如何处理，为什么仍应警惕？
展开答案

① 填补参数从验证数据中学到了统计规律，验证集已不再独立。② 2.828；训练均值是 4，训练标准差是 √2。③ 使用训练期确定的类别字典，handle_unknown="ignore" 可输出全零但不能让模型理解“雪”的真实作用；需要监控未知类别和数据分布变化。
