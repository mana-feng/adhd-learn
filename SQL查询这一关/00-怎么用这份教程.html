00 · 怎么用这份教程

⏱ 30 分钟 · 这是入口与查阅页，可以选好第一站就开始，不要求一次读完。

🎯 一句话

先说清楚“每行代表什么”，再把你要问的问题写成 SQL。 查询不报错，仍可能漏行、重复计数或算错分母。

还没写过 SQL留在本页，运行一个只有三行数据的分组例子，不需要先找外部练习站。 连接后行数或金额变多了检查一行匹配几行，先定位重复从哪里来。 加了条件，结果却消失了先看 NULL 与三值逻辑，再查 NOT IN 和过滤条件。 结果对，但查询很慢从执行计划看实际访问路径，不凭“有索引”就断定快。

🧰 四、先运行三行数据的小实验

现在要问：chat 和 summary 各花了多少？ 本例使用 Python 自带的 sqlite3；SQLite 是嵌入式数据库，不需要额外启动数据库服务。

  1. 新建名为 sql_demo.py 的文件，把下方整段代码复制进去。
  2. 在这个文件所在文件夹打开终端，执行 python sql_demo.py。Windows 已配置 Python 启动器时，也可以用 py sql_demo.py。
  3. 如果命令找不到 Python，先到 ML 首课的运行说明完成环境步骤；现在也可以先看下方输入与结果的对应。
import sqlite3

db = sqlite3.connect(":memory:")          # ⭐ 不装任何东西，库就在内存里
db.execute("CREATE TABLE calls(user_id TEXT, feature TEXT, cents REAL)")
db.executemany("INSERT INTO calls VALUES(?,?,?)",
               [("u1", "chat", 0.056), ("u1", "summary", 2.64), ("u2", "summary", 10.2)])

for row in db.execute("SELECT feature, SUM(cents) FROM calls GROUP BY feature"):
    print(row)

print("sqlite 版本:", sqlite3.sqlite_version)

先看输入，再看分组结果

user_id feature cents（分）
u1 chat 0.056
u1 summary 2.64
u2 summary 10.2

查询按 feature 分组。chat 只有一行，合计 0.056；summary 的两行相加，2.64 + 10.2 = 12.84。

运行时核对这两组值

featureSUM(cents)，单位：分
chat0.056
summary12.84

历史记录的两行打印形式为 ('chat', 0.056) 和 ('summary', 12.84)，版本行为 sqlite 版本: 3.50.4。你本机最后一行显示自己的版本，不需要为了匹配这个数字换环境。

本例没有 ORDER BY，因此两组的返回顺序不作保证。先核对每组的值；业务上要求固定顺序时，应明确指定排序。

这里用 REAL 演示聚合，不是生产记账方案；涉及精确金额，应按业务口径选择整数最小单位或支持的精确小数类型。内存库只存在于本次进程中，程序退出后不保留这些表。

不同数据库，不能只当成换函数名

SQLite 降低了起步成本，但数据库间也有类型转换、聚合合法性、排序和 NULL 处理等差异，不只是语法糖。看 SQLite 官方差异说明与无 ORDER BY 的顺序约定。

原稿的环境记录为 Windows 11、Python 3.13.14、SQLite 3.50.4；它是历史记录，不是本教程要求安装的唯一版本。迁移到其他数据库前，去附录 A核对目标版本并重新运行。

📐 五、怎样验证一段查询

  • 先找输入：完整实验包含建表与数据；标为片段的 SQL，要在指定表上运行，不能把每个语法示意都当成独立程序。
  • 再读每行的含义：查明聚合前后行粒度、计数对象、NULL 与过滤条件。
  • 最后对照结果：数值吻合还要检查口径。耗时受数据、索引、缓存、计划和硬件影响，绝对值与提速比例都不能保证复现。

现在能解释 summary 的 12.84 从哪两行来，就可以先停。下一步改变一条输入金额，再运行查看对应组是否变化。
