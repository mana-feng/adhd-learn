B05 · 多分类与 Softmax：从三个分数到三个概率

⏱ 阅读约 20 分钟 · 动手实践另计

如果订单不仅有“是否超时”，还分“准时、轻微超时、明显超时”，怎样计算概率？

前面的逻辑回归解决二分类。现在我们不跳过分数计算，亲手把三个原始得分变成和为 1 的概率分布，再解释为什么训练中要使用交叉熵。

学完后，你能手算 Softmax 和多分类交叉熵，解释“最大分数”和“真实标签”分别做什么，推导 ∂L/∂zₖ=pₖ−yₖ，并运行一个无第三方依赖的 Python 例子。

前置：03 · 线性模型、03b · 损失函数、B03 · 梯度下降、03a · 二分类。公共路线下一站：05 · 模型评估。03c 为进阶选读。

一、先说清类别到底是什么

我们沿用人为构造的外卖配送任务。实际时长记为 t（分钟），新定义三个互斥类别：

编号类别送达后才知道的标签判定示例
0准时t ≤ 3027 分钟
1轻微超时30 < t ≤ 4034 分钟
2明显超时t > 4048 分钟

注意边界：恰好 30 分钟属于类别 0；40 分钟属于类别 1。这里与 A04 的“严格超过 30 分钟才算超时”一致。

这个任务叫单标签多分类：一条订单只有一个正确类别。若一张图片可以同时包含猫和狗，那是多标签任务，不应该把 Softmax 当成所有任务的通用输出层。

二、一个订单，为什么需要三个 logit

03a 的线性部分产生分数 z=wx+b。多分类把它扩展到每个类别各一组参数：

z₀=w₀·x+b₀；z₁=w₁·x+b₁；z₂=w₂·x+b₂

x 是下单时能拿到的输入特征向量；wₖ 是类别 k 的权重向量；bₖ 是该类别的偏置；· 表示按特征逐项乘权重再相加。zₖ 叫 logit，即模型的原始分数，可以是任意实数，不是概率。

先不考虑这些参数如何训练，假定某张历史订单的原始分数为 z=[2,1,0]。第 0 类得分最大，但这不代表模型一定预测对。

三、从任意分数变成和为 1 的概率

直接用“分数除以分数总和”是不可靠的，因为 logit 可以是负数、总和也可能为 0。我们先取指数 exp(z)=eᶻ，其中 e≈2.71828，让每个数都成为正数；再除以指数之和：

pₖ = exp(zₖ) / Σⱼ exp(zⱼ)

k 是当前类别，j 遍历全部类别；Σⱼ 表示求和，pₖ 是得到的类别概率。所有概率均为正且总和为 1。

完整代入 [2,1,0]：

  1. exp(2)≈7.389056；exp(1)≈2.718282；exp(0)=1。
  2. 分母 S≈7.389056+2.718282+1=11.107338。
  3. p₀=7.389056/S≈0.665241，p₁=2.718282/S≈0.244728，p₂=1/S≈0.090031。
  4. p₀+p₁+p₂≈1。当前预测是最大概率的类别 0，即“准时”。

如果这张订单实际送达 34 分钟，真实类别是 1（轻微超时）。预测类别 0 与真实类别 1 不相同；接下来训练损失就负责衡量这个差距。

四、交互：分数、预测与真实标签

滑块控制的是三个原始 logit；切换真实类别不会改变 logit，但会改变损失。

准时（0）
66.5%
轻微超时（1）
24.5%
明显超时（2）
9.0%
当前预测准时（0）
真实类的概率0.245
交叉熵损失1.408

概率约 66.5%、24.5%、9.0%；预测准时，真实轻微超时；交叉熵约 1.408。

尝试一：把 z₁ 调到 3，观察真实类别概率增大而损失下降。尝试二：保持三个分数不变，仅把真实类别切换成 0；预测结果没变，训练损失却会改变。

五、多分类交叉熵从哪里来

我们希望模型给真实类别的概率 p_true 越高越好。为了把这个目标变成可求导的损失，使用负对数：概率接近 1 时损失接近 0，接近 0 时损失变得很大。

L = −ln(p_true)；若真实类别用独热向量 y 表示，也可以写成 L = −Σₖ yₖ ln(pₖ)。

ln 是以 e 为底的对数；L 是当前这条样本的损失；y=[0,1,0] 表示真实类别是 1，其余位置为 0。实际训练批次通常对各条样本的损失取平均。

本例 p_true=p₁≈0.244728，完整代入：

L=−ln(0.244728)≈1.407606。

如果真实类别是 0，同一概率分布下损失为 −ln(0.665241)≈0.407606。交叉熵衡量的不是模型“猜中了几个”，而是模型为真实类别分配了多少概率。

二分类的 Sigmoid 和三分类的 Softmax 有什么关系？

如果两个 logits 是 [0,s]，第二类 Softmax 概率为 exp(s)/(1+exp(s))=Sigmoid(s)。它们是有关联的；但三分类需要让三个互斥类别的概率加起来等于 1。三个独立 Sigmoid 可以分别超过 0.5，更适合多标签任务。

六、从交叉熵推到参数更新

不能只背结论。先把真实类别的概率代入损失，并利用 ln(a/b)=ln(a)−ln(b)：

L=−ln(exp(z_true)/Σⱼ exp(zⱼ))

L=ln(Σⱼ exp(zⱼ))−z_true

第一项对 zₖ 求导，按链式法则得到 exp(zₖ)/Σⱼ exp(zⱼ)=pₖ；第二项只在 k 等于真实类别时导数为 −1，否则为 0。因此：

∂L/∂zₖ=pₖ−yₖ

这里使用的基础求导规则是 d(ln u)/du=1/u 和 d(exp z)/dz=exp z。不熟悉变化率和链式法则，可回到 B03。

将 p≈[0.665,0.245,0.090]、y=[0,1,0] 代入：

∂L/∂z≈[0.665−0,0.245−1,0.090−0]=[0.665,−0.755,0.090]。

真实类别 1 的梯度为负，沿负梯度更新将增加它的 logit；另外两个梯度为正，会被降低。若 zₖ=Σⱼ wₖⱼxⱼ+bₖ，那么 ∂L/∂wₖⱼ=(pₖ−yₖ)xⱼ，∂L/∂bₖ=pₖ−yₖ，通过链式法则回到模型参数。

七、为什么实现时先减最大值

直接计算 exp(1000) 可能造成数值溢出。Softmax 有个重要性质：给所有 logits 减去同一常数，最后的概率不变，因为分子和分母会同时乘上同一因子。

softmax([1000,999,998])=softmax([2,1,0])；实现中通常减最大分数：[1000,999,998]−1000=[0,−1,−2]，最大指数变为 1，不需要计算巨大指数。

import math

logits = [2.0, 1.0, 0.0]
true_class = 1
shift = max(logits)
scores = [math.exp(z - shift) for z in logits]
total = sum(scores)
probs = [s / total for s in scores]
loss = -math.log(probs[true_class])
grad_logits = [p - (i == true_class) for i, p in enumerate(probs)]

print([round(p, 4) for p in probs])         # [0.6652, 0.2447, 0.09]
print(round(loss, 4))                        # 1.4076
print([round(g, 4) for g in grad_logits])    # [0.6652, -0.7553, 0.09]

在 PyTorch 中，CrossEntropyLoss 通常直接接收原始 logits 和整数类别标签，内部处理数值稳定的交叉熵。不要先 Softmax 后又把概率作为 logits 传进去；详见 PyTorch 实战。

八、检查自己真正理解了吗

  1. 如果 logits 为 [1,1,1]，三个概率各是多少？
  2. 真实类别为 2 时，按本例概率 [0.665,0.245,0.090]，交叉熵是多少？
  3. 为什么“真实类别是 1”不等于“超时概率是 1”？
展开数值答案

① 每类都是 1/3≈0.333。② −ln(0.0900306)≈2.407606，因为真实类只拿到约 9% 的预测概率。③ 1 在这里是类别编号，即“轻微超时”，不是一个概率数值。

到这里你已经能解释：三个 logits → Softmax 概率 → 多分类交叉熵 → 概率减标签的梯度。
