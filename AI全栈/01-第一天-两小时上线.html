01 · 第一天：先在本地跑通，再准备上线

⏱ 阅读时间仅供参考 ｜ ⭐ 核心 ｜ 可分次完成 ｜ 先交付本地流式演示

🎯 一句话

先用两个文件跑通“输入一句话 → 浏览器逐步显示响应”。 默认使用模拟响应，不需要模型账号。它验证网页到后端的链路，不代表真实模型能力或已经公网部署。 这一版故意缺一大堆东西——缺什么、分别在第几章补，末尾那张表就是整个板块的路线图。

🧩 一、把三个完成状态分清

状态 能观察到什么 还不能说明什么
本地跑通 本机浏览器能收发模拟响应 别人可访问、真实模型可用
部署准备 文件、依赖、启动命令与配置已检查 平台服务已经运行
公网验收 停掉本机服务后，另一网络仍可完成请求 已具备生产安全性与稳定性

内网穿透可以临时演示，但仍依赖本机进程。平台服务也可能休眠或中断，不能只凭“有网址”认定可靠。

本页边界： 公网部分是准备与验收清单，不是已实跑的某平台操作教程；没有“两小时一定完成”的保证。

🧩 二、最短路径的四个选择

位置 选什么 为什么是这个形状
后端 FastAPI，一个文件 要一个「能异步、能分批往外写响应」的 HTTP 框架。这两条是硬需求，框架名字 🗓️ 会变
前端 一个 HTML 文件，原生 JS 现在要验证的是链路通不通，不是构建工具链。暂时不引入额外的打包工具
模型 先用模拟响应，按需再接云 API 自建推理是另一条路（全景导论 07 展开），第一天不走
部署 能跑常驻进程的平台 核对流式支持与限制，不只按平台类别判断

🧩 三、后端：先说形状，再看代码

① 密钥必须从环境变量读。 不只是安全洁癖——环境变量是常见配置入口；平台也可能支持挂载文件或密钥服务。写进代码意味着每换一次 Key 都要重新提交、重新部署，而且这份代码从此不能公开。

② 需要一个「能分批往外写、且连接保持打开」的返回方式。 浏览器要边收边显示，就不能等模型生成完再 return。FastAPI 里这东西叫 StreamingResponse，喂它一个生成器，yield 一次它就往连接里写一次。

③ 往外写的东西要分帧。 你迟早要往回送「不是正文」的东西——错误、用量、工具状态。先分帧，以后加东西不用重写前端。

用 SSE：每帧一行 data: {JSON}，帧间空一行，帧的类型放在 JSON 负载的 type 字段里（delta / usage / error / done）。

⭐ 类型不放进 SSE 的 event: 行，是因为前端用 fetch 手动解析（第四节说了为什么不用 EventSource），这里的简化解析器只读 data 行；完整解析器也能读 event 行。放进 JSON 是本例约定。

⭐ 全板块统一这个格式，05 / 10 都照它来。

# app.py —— 本地教学演示，公开前需补安全与稳定性
import json, os, time
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse, FileResponse, JSONResponse

app = FastAPI()
API_KEY = os.environ.get("ANTHROPIC_API_KEY")      # ⭐ 密钥从环境变量读
MODEL = os.environ.get("MODEL")                    # 接真实服务时配置账号可用的模型 ID


def stream_from_model(prompt):
    """一段一段产出文本。没配 Key 就用假模型，用于先验证本地链路。"""
    if not API_KEY:
        for ch in "（假模型）我收到了：" + prompt:
            time.sleep(0.02)
            yield ch
        return
    if not MODEL:
        raise ValueError("接真实模型前，请设置账号可用的 MODEL")
    import anthropic                                # pip install anthropic
    client = anthropic.Anthropic(api_key=API_KEY)
    with client.messages.stream(model=MODEL, max_tokens=1024,
                                messages=[{"role": "user", "content": prompt}]) as s:
        for piece in s.text_stream:                 # ⭐ 生成一点就往外吐一点
            yield piece


@app.post("/api/chat")
async def chat(req: Request):
    prompt = (await req.json()).get("prompt", "").strip()
    if not prompt:
        return JSONResponse({"error": "prompt 不能为空"}, status_code=400)

    def sse():                                      # ⭐ 每帧一行 data:，帧间空一行
        for piece in stream_from_model(prompt):     # ⭐ 类型放负载里，不用 event: 行
            yield "data: " + json.dumps({"type": "delta", "text": piece},
                                        ensure_ascii=False) + "\n\n"
        yield 'data: {"type":"done"}\n\n'           # ⭐ 结束帧也是一帧正常 JSON

    return StreamingResponse(sse(), media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache",
                                      "X-Accel-Buffering": "no"})   # ⭐ 请代理别缓冲


@app.get("/")
def index():
    return FileResponse("index.html")

⚠️ 两个细节：没 Key 就走假模型——第一天最怕「装了半天环境卡在 401」，把「链路通不通」和「Key 对不对」分开排查（import anthropic 也因此放在函数里）；X-Accel-Buffering: no 是发给中间层的请求，Nginx 那类代理默认攒够一批再转发，那样流式就白做了。

🧩 四、前端：核心就是「读流 + 拼帧」

⚠️ 别用 EventSource。 它只能发 GET，问题就得塞进 URL——长文本超限、换行要转义、还进浏览器历史。用 fetch 拿到 response.body 自己读，也就多五行。

<!doctype html>
<meta charset="utf-8">
<textarea id="q" rows="3" style="width:100%"></textarea>
<button id="go">发送</button>
<div id="out" style="white-space:pre-wrap"></div>
<script>
const out = document.getElementById('out');
document.getElementById('go').onclick = async () => {
  const prompt = document.getElementById('q').value.trim();
  out.textContent = '';
  const resp = await fetch('/api/chat', {method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({prompt})});
  if (!resp.ok) { out.textContent = '出错了：HTTP ' + resp.status; return; }

  const reader = resp.body.getReader();
  const decoder = new TextDecoder();   // ⭐ 整个流复用同一个，才能拼回被切断的中文
  let buf = '';
  while (true) {
    const {done, value} = await reader.read();
    if (done) break;
    buf += decoder.decode(value, {stream: true});   // ⭐ stream:true 是关键
    const frames = buf.split('\n\n');
    buf = frames.pop();                             // ⭐ 最后一段可能是半个帧，留下
    for (const f of frames) {
      if (!f.startsWith('data: ')) continue;
      const frame = JSON.parse(f.slice(6));        // ⭐ 每帧都是合法 JSON，解析路径只有一条
      if (frame.type === 'done') return;           // ⭐ 正常收尾的标志
      if (frame.type === 'delta') out.textContent += frame.text;
    }
  }
};
</script>

⭐ 这两处缓冲分别处理“半个字符”和“半条消息”。 一次网络读取不保证恰好得到完整字符或完整 SSE 帧。

  • decoder.decode(value, {stream: true})：先保留不完整的 UTF-8 字节。常见汉字通常占 3 字节，也有 4 字节字符；如果切片从字符中间断开，直接逐片解码可能出现 �。只测 ASCII 文本不容易发现这个问题。
  • frames.pop()：先保留最后一段，等下一批数据补齐。例如刚收到 data: {"te 时还不能解析 JSON；遇到帧分隔符后再处理完整消息。

字符缓冲的参数说明可查 MDN：TextDecoder.decode 的 stream 选项。本例前端只约定了后端发出的这类数据帧，不是完整的通用 SSE 解析器。

🧩 五、先跑通本地模拟响应

准备： 已安装的 Python、终端和浏览器。新建文件夹，把第三节保存为 app.py，第四节保存为 index.html；在这个文件夹打开终端。

第一次使用没有配置 ANTHROPIC_API_KEY 的环境，避免意外调用收费 API。下面只安装本地 Web 服务依赖：

python -m pip install fastapi uvicorn
python -m uvicorn app:app --reload --port 8000

保持终端运行，在浏览器打开 http://127.0.0.1:8000。不是双击 index.html，也不是把这个地址发给朋友。

做什么 应观察到什么
输入“你好”，点击发送 “（假模型）我收到了：你好”逐步出现；分批可能受缓冲影响
输入中文 文字完整，没有替换字符 �
空输入发送 “出错了：HTTP 400”

找不到 app，先检查终端目录；缺 fastapi 或 uvicorn，确认安装与启动使用同一个 Python。停止服务后页面不能继续请求，说明它仍依赖本机进程。

本地验证记录（2026-09-08）： 本页原样代码在 FastAPI 0.141.1、Uvicorn 0.52.4 下通过浏览器测试：中文模拟回复完整显示，空输入返回 HTTP 400。记录仅覆盖无密钥的本地路径，不代表其他版本、真实模型或公网部署已通过。

接真实模型是另一步： 安装 anthropic SDK，配置 ANTHROPIC_API_KEY 与账号可用的 MODEL。接口、模型名和费用需查服务商当前文档；本页本地测试不验证外部调用。

🧩 六、部署准备：暂不算公网验收

此处没有完成外部平台实跑。 先准备，再部署，最后做跨网络验收：

准备项 要确认什么
依赖 requirements.txt 记录本地验证过的版本
启动 平台要求的监听地址与端口；是否经过 shell 展开变量
流式 应用、平台和代理都允许及时转发响应
资源 请求时限覆盖目标响应；冷启动和并发可接受
配置与安全 HTTPS、密钥管理、访问控制、配额、日志与错误处理

常驻容器可以是一个选项，但 Serverless 并非默认不可用；部分函数平台支持流式，仍需核对其运行时与限制。Vercel 官方流式文档

如果平台提供 PORT 环境变量，并要求监听所有网卡，POSIX shell 中常见启动方式为：

python -m uvicorn app:app --host 0.0.0.0 --port "$PORT"

这不是所有终端都通用的命令。PowerShell 使用 $env:PORT；没有 shell 的启动配置可能不会展开变量。平台不提供 PORT 时，按文档填写端口。

部署后，用另一网络完成一次请求；停止本机服务后再测。只打开首页不等于接口可用，还要检查中文、空输入、错误响应与分批到达。

公开真实模型接口前先补护栏。 当前没有登录、配额与可靠异常处理，不要将带收费密钥的无保护端点直接开放。

🧩 七、⭐ 这一版缺什么（= 整个板块的路线图）

先按当前目标选一行，不需要立刻完成整张表。 本地模拟演示可以停在上一节；准备公开收费模型接口时，先检查访问控制、密钥和成本护栏。

十七行保留了后续主题与章节入口；编号用于查找，不是适用于所有项目的优先级或必修顺序。

# 缺什么 现在的后果 在哪补
1 ⭐ 没有限流和配额 公开收费接口后，重复或恶意请求可能消耗预算 12 章 限流与成本护栏
2 ⭐ 配置分环境与密钥轮换仍需完善 环境变量避免把密钥写进源码，但泄露后仍要撤销、替换并更新运行配置 13 章 配置与密钥
3 ⭐ 跨域、CSRF、XSS 边界尚未完整验收 当前用 textContent 显示纯文本；以后加跨域、Cookie 登录或富文本时，应分别检查相关安全边界 08b 同源策略与 CORS · 08c CSRF 与 XSS
4 ⭐ 缺少业务日志、指标与请求关联 服务启动日志不足以解释某次模型请求为何失败或变慢 15 章 可观测性
5 ⭐ 重复请求没有幂等控制 用户重发或以后加入自动重试时，可能重复生成并产生额外费用 03c 幂等与条件请求
6 未明确应用的超时、重试与缓存策略 上游失败时可能中断响应；SDK 默认行为不等于应用已有完整恢复策略 04 章 调用层
7 ⭐ POST /api/chat 尚未定义兼容与演进约定 接口可以改，但已有客户端依赖它时需要兼容安排 03b 接口的形状
8 流式取消与中途失败尚未验收 要确认关页面后上游是否停止，以及部分回复出错时如何提示 05 / 10 章
9 没有数据库 请求与回复不能持久保存，刷新后无法恢复 06 章 关系数据库
10 没有登录或其他访问控制 当前接口不能验证调用者身份，也不能隔离不同用户的数据 08 章 · 08d OAuth2 与 OIDC
11 示例尚未配套项目内的自动化测试 除了协议与错误处理，还需要按任务评估模型输出；不能只靠固定全文相等判断生成质量 15b 怎么测不确定的系统
12 改一行要手动重部署 越怕出事越不敢发版 14 章 容器化与部署
13 界面只有基础发送与报错 还需加载状态、取消操作，以及读者能理解的恢复提示 09 章 最小可用前端
14 长任务依赖当前请求连接 耗时任务若需断线后继续、重试或排队，应设计后台任务机制 11 章 长任务与队列
15 没有自动检索自己的资料 可以手动把少量文字放进输入，但尚不能从资料库中检索相关片段 07 章 向量检索落地
16 没有文件上传与存储 不能直接上传文档；粘贴文本不等于具备文件处理能力 07b 文件上传与对象存储
17 没有「我的历史对话」列表 加存储后还需列表接口；数据变化时要检查分页的重复与漏项 06b 列表接口与分页

按影响范围安排下一步。 只在本机跑模拟回复，可以先理解请求与响应；准备让别人调用真实模型，应先检查身份、权限、密钥、配额和错误处理，同时保留排查问题的日志。

一条接口本身不是缺陷。 第 7 行要补的是字段、错误格式与兼容约定。已有客户端时，改名或删字段需要迁移安排；并不是接口一旦发布就永远不能修改。

第 3 行的前提可查 MDN：textContent 与 innerHTML 的区别。纯文本插入不等于将模型输出作为 HTML 执行，也不代表整个应用已完成安全验收。

💡 带字母后缀的行（03b / 03c / 06b / 07b / 08b / 08c / 15b）补的是「这个零件本来的规矩」， 主编号的章补的是「它被 AI 那四件事咬到的那一面」。⭐ 赶时间可以先跳过后缀章把主干跑通。

🔄 换个栈怎么对应

概念 FastAPI Node（Express / Hono） Go
分批往外写响应 StreamingResponse(生成器) 多次 res.write() / 返回 ReadableStream w.Write() + Flusher.Flush() ⭐
读环境变量 os.environ.get process.env os.Getenv
监听所有网卡 --host 0.0.0.0 app.listen(port, '0.0.0.0') ListenAndServe(":"+port, h)

⭐ Go 的 ResponseWriter 默认带缓冲，不手动 Flush 就攒着不发——可见「分批往外写」在每个栈里都要显式表达，只是 FastAPI 把它藏进了名字里。

✅ 检查点

  1. 本地跑通与公网验收有什么区别？
  2. 模拟响应能验证什么，不能验证什么？
  3. 流式返回有什么要求？为什么前端要保留半帧？
  4. event 行是否只能被 EventSource 理解？
  5. 判断平台能否使用，要检查什么？
  6. 公开真实模型接口前还缺什么？
👀 答案
  1. 本地只证明本机链路；公网还需另一网络的实际请求，且不依赖本机服务。
  2. 可验证收发链路，不能验证真实 API、权限、模型能力或公网部署。
  3. 应用与代理都需及时转发；流式解码保护跨分片字符，保留半帧避免 JSON 未收全就解析。Go 中还要注意刷新缓冲。
  4. 不是。完整 SSE 解析器也能读它；本例把类型放在 JSON，是简化解析的约定。
  5. 流式支持、资源与时限、启动和端口、HTTPS、配置、安全与成本，不能只看平台类别。
  6. 访问控制、配额、密钥保护、超时与错误处理、日志和部署检查；环境变量不等于完整安全体系。

⚡ 走神救援

  • 先做本地模拟响应，不把它当成真实模型或公网上线。
  • 两个文件同一目录，安装与启动使用同一个 Python。
  • 流式解码保住多字节字符，缓冲区保住尚未收齐的帧。
  • 外部 API 与公网分别验证，公开前补安全护栏。
