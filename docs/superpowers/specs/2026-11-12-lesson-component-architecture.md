# ADHD-Learn 课程组件架构规范

日期 2026-11-12。配套 [分阶段实施计划](../plans/2026-11-12-lesson-component-migration.md)。沿用 [维护与定向重建](../../../maintenance/README.md)、[知识架构开发合同](2026-11-10-knowledge-architecture-development-contract.md) 和 [固定深黑代码主题](2026-10-28-unified-code-theme-design.md)。

## 目标与边界

课程维护源承担教学正文和明确的组件声明。布局、重复样式和阅读增强各自有唯一的维护入口。发布页保留可以直接阅读的静态 HTML，随站点资产离线可用。URL、片段 ID、旧书签、进度键、导航方向与现有操作顺序视为兼容接口。此规范描述逐批迁移路径，每批以正式映射中的明确消费者为边界。

| 层 | 权威数据 | 输出和兼容责任 |
| --- | --- | --- |
| 教学内容 | `maintenance/polished-pages.json` 选中的 Markdown 或恢复 HTML | 标题、段落、公式、图注、例题、代码、表头、检查题和答案由课程源维护。结构变更先核对知识坐标、先修和下游，再更新知识基线 |
| 布局与资源 | 正式映射的 `template`、标题、前后章链接与现有可选字段。专用布局可放 `maintenance/templates/*.html.tmpl` | 构建期生成 head、顶栏、main、导航和必要静态降级。路径按发布页位置解释。Markdown 与恢复 HTML 的过渡路线各自可回滚 |
| 外观 | `assets/` 中按职责组织的 CSS，含现有模块变体 | 先匹配现有级联、选择器作用域和响应式断点。共享样式使用页面已有 token。代码 palette 仅归 `assets/code-reader.css` |
| 阅读增强 | 既有 JS 和章内明确的 `data-*`／JSON | 在已有静态语义上增强，明确根节点、依赖和加载顺序。保存状态不可用或功能初始化失败时可用原链接、原生折叠和正文 |
| 取证 | 正式规范和计划版本化，生成式快照与截图留本地 | 对照相同源修订，区分静态覆盖、实际浏览器状态、未验证场景和上下游影响 |

### 组件接口规则

- 构建器从正式映射接收路径，使用现有路径约束、转义与 Markdown 渲染。首批保留现有 `<main>` 与 `donebar` 分界。更通用的模板系统需要显式槽和唯一占位，遇到缺失、重名、越界或重复输出时给出可定位失败。接入前应能按组件列出直接与间接消费者。
- HTML 恢复源维持当前逐字节复制入口。将来确需在 HTML 源使用构建期组件时，单独引入显式接入机制和与之相配的一致性验证，避免全站自动按类名改写。
- 教学语义、公式数据和课内例子与展示分开。对图、代码、公式保留原静态表达。富交互可以使用同源、本地加载的增强脚本。正文、目录和主要导航无需运行时获取组件或数据。
- 资源依赖分层管理。首屏恢复主题先于页面绘制。章级脚本在 DOM 和既有依赖可用后绑定，允许重复初始化保护。图文与代码增强的顺序、KaTeX 与公式资料注册按现有消费者实测。过渡期保留既有资源 URL。公共代码 palette 的所有权与主题行为遵循已发布规范。
- 不扩大数据职责。正式映射持有生成与导航所需字段。现有本地 JSON 提供明确的章内数据。维护源、组件和已生成输出保留可追溯关系。进度、现有教学标识及路径不会由模板派生新值。

### 路线取舍

构建期专用布局适合静态 HTML 与 Markdown 主线，可在现有构建器上验证小范围接入。共享 CSS 和渐进增强适合外观与行为，既有实现已覆盖多数代码和阅读工具。HTML 显式占位适合第二批之后的恢复页结构迁移，代价是新增构建接口和消费者检查。结构化数据优先沿用既有 JSON。Web Components 仅评估可隔离的选用控件，保持静态正文。Markdown 迁移由教学结构保真和实际维护收益决定。

- [AI 全栈 03c](../../../AI全栈/03c-幂等与条件请求.html) 放大图示时曾实测克隆产生重复的 SVG 标题和描述 ID。图示共享批次需覆盖副本 ID 和所有内部引用。原 SVG 的锚点、标签、图注和计算保留。

## 组织与提交

统一在阅读基础设施名下维护接口和验收，按组件保留各自文件。已有页面、模板和资源由唯一编辑负责人定向修改。规范与计划和行为实施可分别提交，所有 Codex 提交沿用仓库配置身份及一个 Codex 共同作者记录。本轮本地验证。
