| P2 · 静态外壳与导航 | **本轮 LoRA 05b 单页**。切换到专用模板，模板仅含当前所需的框架。05 为只读对照。后续评估第二个 Markdown 变体和两课 HTML 显式接入 | 初版验证逐字节等价。代码配色修订保留首个内联样式之外的全部字节。回滚正式映射指针与专用模板 |

## P2 单页试点

### 授权范围与数据

- 模块为大模型全景导论。唯一输出是 `大模型全景导论/05b-LoRA从数据到验收.html`，权威正文是 `_src/大模型全景导论_md/05b-LoRA从数据到验收.md`。
- 初版模板取自完整 05 课。现有渲染器使用 `<main>` 之前及 `<div class="donebar">` 起的后段，中间教学内容被忽略。05 章自有源、05 章生成页、05b 正文和既有构建器均作为比较基线。代码配色修订仅改变首个内联样式，正文及其 S/P 坐标保持。
- 实施文件为 `maintenance/templates/llm-lesson-v1.html.tmpl` 与 `maintenance/polished-pages.json`，以及这份计划与配套规范。配色修订另包含 05b 的定向生成页。其余 42 个 Markdown 输出仍按初版指纹核验。
- 05b 保留 `overview-progress`、现有 Markdown 文件名键、原相邻章及原资源顺序。此轮专用布局只有一个消费者，用于验证模板与教学正文的边界，实际的多页复用留待第二个消费者的迁移验证。

### 步骤与可检查结果

1. 冻结现有 HEAD、正式映射、05、05b、Markdown 源、构建器和运行依赖。读取三份只读报告，对照它们所用的修订及计数口径。
2. 用外部验收先断言 05b 已引用专用布局，观察旧映射失败。记录现有 43 个 Markdown 输出的渲染指纹。
3. 用现有 05 模板的前后段形成专用布局。正文槽留空。标题、顶栏上一章／下一章、章末导航及 FILE 由现有生成器填写。模板保持声明边界、资源顺序、行尾和原有存储命名空间。映射只修改 05b 的 `template`。
4. 从正式映射筛选 05b，仅调用现有构建器处理该条。比较输出与基线 SHA-256。以只读方式重渲染 43 条 Markdown 对照，验证既有 05 和旧模板其他消费者的指纹，扫描链接、重复 ID 与依赖。运行维护单元测试。
5. 用 Chromium 对照 1440／390、亮暗、无 JavaScript 与本地断网。检查首页／目录／前后章链接、原有 `#token` 深链接、检查点折叠、历史打卡与主题重载、三个原生代码片段的实测颜色。现有 JavaScript 或课程行为已知问题只在本批记录。
6. 实际结果写回计划并审查 Git 文件边界。获得对应提交授权后，用仓库用户身份提交，末尾加 `Co-authored-by: Codex <codex@openai.com>` 一次，提交后使用 `git show` 核对。

### 回滚与扩展条件

若 05b 出现授权样式范围之外的字节变化，或可访问性、导航、旧键回归，按当前审阅范围撤回。只撤回配色修订时，恢复该版模板并定向生成 05b。撤回布局隔离时，恢复原模板指针，仅定向生成 05b，移除无消费者的新模板并比对基线。试点验收只覆盖该入口。扩展时每批明确变体和消费者，再单独检查新加载关系。

## C1 初版历史证据

- 三份只读审计完成。已将视觉组件的候选规则族、共享阅读行为的兼容条件和模板边界纳入规范。文档与试点作用域共四个仓库文件，后续批次保留现有资产地址和兼容入口。
- 05b 的专用模板体没有教学正文。旧捐赠模板中被渲染器跳过的部分为 22,098 UTF-8 字节，仍完整留在 05 课程源。正式映射只改 05b 的模板指针。没有修改构建器、05 课程、05b Markdown 或输出。
- 实际调用构建器处理一个映射条目。05b 的 SHA-256 仍为 `c110326dc0a767442b7a321297bfbbb78a6582bdef82ea8c85e9d4672116b922`，文件未被重写。43 个 Markdown 输出经内存重渲染均逐字节相同，另外 560 条映射不变。正文教学结构、文章、章节、段落和候选要点无变动。
- 26 个本地链接及资源引用、8 个唯一 ID、8 个原生检查点折叠、3 个原生代码块通过静态核对。维护单元测试 12 项通过。
- Windows Chromium 执行 368 项检查。1440／390、浅／深及有／无 JS 的 16 个前后对照状态中，8 组截图逐像素一致。另通过两个 `file://` 离线状态，共保存 18 张截图。原书签、前后章、检查点、旧打卡与保存主题重载通过。54 个原生代码取样均为 `#1e1e1e`，最低文字对比度 12.51:1。该页没有专用续读或动态代码查看器。真实手机、屏幕阅读器与跨浏览器运行未覆盖。

## 下一批的试点建议

先从两个现有同族页面抽取字节相同的字体、字号和正文节奏规则，保留模块变体和断点。以 AI 全栈旧版章节及已验收的 AI 基础设施 07／08 做计算样式对照。表格滚动壳与 JS 增强的边界另用 AI 全栈 03b、智能体 Markdown 表格和 NumPy 02 验证。每批先做小范围落地，核对消费者后再扩到同族。

## C1 配色修订

主会话指出初版专用模板仍携带旧代码配色。修订移除模板的旧代码背景、前景、行号和 Pygments 语法颜色，保留非颜色布局和字形声明。现有 `assets/code-reader.css` 提供唯一代码 palette。非代码 `.gaprow .who` 使用既有页面 `--quote-bg`、`--fg`。05b 当前没有这个标记。

修订仅定向生成 05b，首个内联样式之外的全部字节与初版一致。旧 05、05b 正文、正式映射、构建器及共享资产保持。其他 42 个 Markdown 输出按初版散列重渲染核对。修订证据独立保存，待主会话复核。

C2 先在隔离预览验证 AI 全栈 01 与 03b 的规则提取，保留原级联位置和静态正文。LoRA 05b 留待 C1 复核后从本修订基线重新计算规则指纹与加载顺序。
