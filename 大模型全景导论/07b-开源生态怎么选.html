07b · 开源生态怎么选，以及要不要自建

⏱ 26 分钟 ｜ ⭐ 自建往往不是「更便宜」，而是「用钱换控制权」

🎯 一句话

上一页证明了「能跑」，这一页回答「值不值得一直这么跑」。 把隐性成本算进去之后，多数场景自建并不更省钱——它买的是合规、隐私和可控；而真要在开源模型里挑一个，最容易踩的坑不是能力，是许可证。

🚦 决策：什么时候该自建

关键信息

  • ✅ 该本地/自建的场景
  • 数据不能出内网（医疗、金融、政务、法务）
  • 稳定大流量，自建单价远低于 API
  • 需要微调后的专有模型（第 5 章）
  • 需要极低延迟（本地无网络往返）
  • 离线环境
  • 学习和实验（免费随便玩 ⭐）
  • ⛔ 不该的场景
  • 流量小且不稳定 → API 按量付费更划算
  • 需要最强能力 → 顶尖闭源模型仍有优势
  • 团队没有运维能力 → 自建的隐性成本是人力
  • 快速验证想法阶段 → 先用 API 跑通再说

💰 粗算一笔账：一张 24GB 消费级显卡 ≈ 几千到万把块。 如果你每月 API 花费不到几百块，自建在经济上不成立——但作为学习投资另说。

💸 自建的"隐性成本"清单（算账时最容易漏）

关键信息

  • 显性成本：显卡 / 云 GPU 租金
  • ⭐ 隐性成本（往往更贵）：
  • 运维人力：模型更新、故障排查、扩容（这是最大的一笔）
  • 闲置成本：GPU 按小时计费，流量低谷时也在烧钱
  • 能力差距：自建模型效果不如顶尖闭源，可能需要更多工程弥补
  • 迭代速度：闭源模型每几个月免费变强，自建的不会
  • 机会成本：花在运维上的时间没花在产品上

🔑 一个反直觉的结论：自建往往不是"更便宜"，而是"用钱换控制权"。 如果你的真实需求是合规、隐私、可控，自建就值； 如果只是"觉得 API 贵"，先去做 Prefix Caching 和提示词优化（06d · 降延迟与指标）， 那些的投入产出比高得多。

🌍 开源模型生态（会变，记结构别记名字）

关键信息

  • 主要开源系列（2026 年前后的格局）
  • Qwen（阿里） —— 中文强、尺寸齐全、生态活跃
  • DeepSeek —— 推理和代码能力突出、MoE 架构
  • Llama（Meta） —— 生态最广、工具链最全
  • Mistral —— 欧洲、效率导向
  • Gemma（Google） —— 小尺寸质量高
  • 各种垂直微调版本 —— 代码/医疗/法律等

选型看四点： 1. 许可证 ⭐ —— 能不能商用？有没有用户数限制？这是最容易踩的坑 2. 中文能力 —— 中文场景优先看国产系列 3. 尺寸 —— 有没有适合你硬件的档位 4. 生态 —— 有没有现成的量化版本、微调脚本、社区支持

⚠️ 时效警告：模型名字和排名几个月就变。上面的列表只用来理解「有哪几类玩家」。 实际选型时去看当前的开源榜单（第 11 章讲怎么正确看榜）。

📦 深挖的话要学什么

下面按交付问题分路。“有相关章节”不代表已经包含你所用版本的完整操作，也不代表你需要全部先学完。

模型如何成为可运行的服务

  • 下一站：AI 全栈 14 · 容器化与部署，多卡原理见 AI 基础设施 12 · 张量并行。
  • 继续看：推理服务化 20 的负载均衡、健康检查与请求取消。
  • 验收：进程存活、服务就绪、代表性推理分别检查；取消请求要沿链路传播并释放资源。模型热切换仍需按引擎验证，不能假设容器能启动就已完成。

流量来了，能承受多少

  • 下一站：服务化压测 与 可观测性与成本。
  • 看什么：吞吐、TTFT、TPOT、KV 占用、排队与尾延迟。
  • 产出：包含闲置、人力与峰值余量的成本表；只报 GPU 利用率或月租都不够。

量化后质量是否还能接受

  • 下一站：AI 基础设施 18 · 量化。
  • 看什么：在自己的任务数据上比较各档位；校准集是否匹配业务只是一个检查方向。
  • 边界：质量下降也可能来自位宽、实现、激活异常和模型本身，不能都归因于校准集。

多个租户能否共用基座

  • 下一站：推理服务化 20，原理配合 05 · 微调与 LoRA。
  • 看什么：多 LoRA 适配器的挂载、批处理、显存预算与隔离。
  • 验收：当前引擎、模型和适配器格式是否真的支持这套组合。共享基座省掉重复权重，不会自动解决租户权限问题。

手机与嵌入式部署

  • 下一站：PyTorch 10 · 把模型交出去。
  • 保留的主题：模型与 state_dict、TorchScript trace/script、ONNX 导出与对拍、torch.compile。它们用途不同，不能都叫“导出文件”。
  • 继续验证：CoreML/TensorRT 转换、手机 runtime、内存和量化质量，需要对应设备与版本的官方说明和实机测试。

把私有知识助手接成系统

  • 下一站：智能体工程 17b · 企业知识助手交付项目；它有实践骨架，也明确标出尚未实现的生产能力。
  • 配套入口：模型服务见 AI 基础设施 20，向量检索见 推荐 10。
  • 监控与预算：基础设施 23、模型上线 05、AI 全栈 12。
  • 交付边界：仍要核验网关、网络隔离、权限、失败恢复与备份；有一个演示项目，不等于已经完成企业部署。

可以停在这里：先判断需要哪种交付能力，再补 Linux、Docker 或推理引擎知识，不必先通读整张工具清单。

⚖️ 要不要深挖

你的情况 建议
从没跑过本地模型 ✅ 强烈建议按上一页那条 30 分钟路线跑一次——认知冲击很大，且免费
有合规/隐私硬需求 ✅ 必须深挖，配合第 6 章
想省 API 钱 🟡 先算账，多数个人场景自建不划算
做企业私有化交付 ✅ 这是核心交付能力
纯做应用、用云 API ⛔ 知道有这回事就行

🔑 我的判断：这块知识密度最低但体验价值最高。 它不值得单独做一整套教程（内容撑不满，且工具变化快）， 但「花半小时跑一次本地模型」这件事本身，对建立直觉很有用—— 你会立刻理解量化、显存、速度这些抽象概念到底意味着什么。

建议：并入第 6 章推理优化，作为它的实操部分。

✅ 检查点

  1. 什么情况下该自建、什么情况下不该？
  2. 自建的「隐性成本」有哪些？为什么说自建往往不是「更便宜」而是「用钱换控制权」？
  3. 只是觉得 API 贵，第一步该做什么？
  4. 开源模型选型要看哪四点？哪一点最容易踩坑？
  5. 为什么这一页的模型名单只让你「记结构别记名字」？实际选型该看什么？
👀 答案
  1. 该：数据不出内网（医疗/金融/政务/法务）、稳定大流量、需要微调后的专有模型、需要极低延迟、离线环境、学习和实验。不该：流量小且不稳定、需要最强能力、团队没有运维能力、还在快速验证想法的阶段。
  2. 隐性成本：运维人力（最大的一笔）、GPU 闲置成本、能力差距、迭代速度落后、机会成本。算上它们之后经济优势往往就没了——真实价值在合规、隐私、可控，所以是用钱换控制权而不是省钱。
  3. 先做 Prefix Caching 和提示词优化（06d · 降延迟与指标）——投入产出比高得多，而且不需要任何运维。
  4. 许可证、中文能力、尺寸档位、生态支持。⭐ 许可证最容易踩坑（能不能商用、有没有用户数限制）。
  5. 因为模型名字和排名几个月就变，名单只用来理解「有哪几类玩家」（中文强的、推理和代码强的、生态最全的、效率导向的、小尺寸质量高的）。实际选型要去看当前的开源榜单，而怎么正确看榜是第 11 章的事。

🛑 可以停在这里

到这里你能给出一个有依据的答案：这件事该自建还是该继续用 API，以及要自建的话从哪个开源系列起步。

⚠️ 什么时候回来：账算完、模型也选好了，但你发现真正的问题是「模型答不上我们自己的资料」——那不是部署问题，是检索问题，去 08 系列。

⚡ 走神救援

先记住这几件事

  • 自建的价值可能是控制权、内网需求或稳定负载，不只是省调用费。
  • 把运维、人力、闲置资源与效果差距算进总成本。
  • 选型同时检查许可证、语言与任务表现、硬件适配和维护条件。
