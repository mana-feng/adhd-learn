02b · 现代 LLM 架构的四处改动

⏱ 66 分钟 ｜ ⭐⭐ 第 2 章那张图今天依然对，但照着它，你读不懂任何一份 LLaMA 代码

🎯 一句话

2017 年的原始 Transformer 和 2026 年的 LLaMA / Qwen，骨架一行没改，但有四个零件被换掉了。 每一处都在修原始设计的一个具体毛病。这一章讲前两处——它们都长在「归一化」这个零件上、而且互相咬合；后两处（SwiGLU、RoPE）各自独立，在 02e。

🚪 一屏代码，四个不认识的东西

第 2 章讲完，你脑子里的一层 Transformer 长这样：

   注意力 → ＋残差 → LayerNorm → FFN → ＋残差 → LayerNorm

这张图是对的。然后你打开一份真实的 LLaMA 实现，第一屏就卡住了：

class RMSNorm(nn.Module):                       # ← 这是什么？PyTorch 不是有 LayerNorm 吗
    ...
hidden = self.input_layernorm(x)                # ← 怎么 norm 跑到注意力【前面】去了
q = apply_rotary_emb(q, freqs_cis)              # ← 这又是什么，位置编码不是加在输入上吗
F.silu(self.gate_proj(x)) * self.up_proj(x)     # ← FFN 怎么有三个矩阵，还要相乘

第 2 章那张图上，这四个东西一个都没有。 你以为自己懂了 Transformer，结果连模型定义文件的第一屏都读不下去。而且这四行不是某个人的花活——几乎所有 2023 年之后的开源模型都长这样。

好消息是：它们改的全是零件，没有一处动了骨架。 第 2 章那张图今天依然成立，你只需要把盒子里装的东西换掉。

🔭 一、骨架一行没改，那到底改了什么

盯着看，右边只有两类差别：盒子的位置变了（归一化跑进了残差分支里），和盒子里的零件被换了。

零件 原始 Transformer（2017） GPT-2 / GPT-3 LLaMA / Qwen / Mistral
归一化位置 Post-LN（残差之后） Pre-LN Pre-LN
归一化种类 LayerNorm LayerNorm RMSNorm
FFN 激活 ReLU GELU SwiGLU
FFN 中间维度 4d 4d 约 8/3 · d（对齐取整）
位置编码 正弦（加在输入） 可学习绝对位置（加在输入） RoPE（乘在每层的 Q/K 上）
归一化的 bias 有 有 没有（连线性层的 bias 也普遍去掉了）

⭐ 中间那一列是这张表最有信息量的部分：四处改动不是一次换完的。 Pre-LN 在 GPT-2 时代（2019）就换了，RMSNorm / SwiGLU / RoPE 是 2021–2023 陆续换的。 所以不同年代的代码会是不同组合，这很正常，不是谁写错了。

🗺️ 二、还没讲原理，你已经能一眼看出模型是哪年的设计

这一节本来在全章最后。但它是这一章里最快能用上的东西，所以提到前面来——读完就能拿去用，后面两节才是「为什么」。

打开任何 HuggingFace 模型目录下的 config.json，每一个字段都是某处改动留下的疤：

字段 它在说什么 哪处改动
rms_norm_eps ⭐ 光是这个字段名出现，就说明用的是 RMSNorm 不是 LayerNorm ②
num_hidden_layers 层数。几十层这个量级本身就意味着它不可能是 Post-LN ①
hidden_size 就是 d。4096 ≈ 7B 级，8192 ≈ 70B 级 ——
intermediate_size FFN 中间维度。除以 hidden_size：约 2.67 → SwiGLU；约 4.0 → 老式两矩阵 FFN ③ 见 02e
rope_theta RoPE 的 base。10000 是原版，500000 / 1000000 说明做过长上下文扩展 ④ 见 02e
rope_scaling 有这个字段 = 做过位置插值一类的外推处理，里面写着 type 和 factor ④ 见 02e
num_attention_heads / num_key_value_heads 两者不等就是 GQA（🔗 KV Cache）——第五处改动，不在本章 ——
max_position_embeddings 宣称的上下文长度。⚠️ 这是宣称值，不是有效值 ——

💡 一个 30 秒的判龄法：看 intermediate_size / hidden_size。 LLaMA-7B 是 11008 / 4096 = 2.6875，贴着 8/3 ≈ 2.667——SwiGLU 家族，2023 年之后的设计。 GPT-2 是干净的 4.0——2019 年的设计。一个比值就能定位年代。

只想读懂代码的话，看到这里其实够了。 想知道这些零件凭什么把前一代挤掉，往下读。

🧨 三、为什么 2017 年那套堆到几十层就训不动了

现象：层数加上去，loss 反而不降了

你手上有一份完全照着 2017 年论文写的 Transformer，6 层，训得挺好。想让它更强，于是把层数改成 48。然后：loss 在前几百步剧烈震荡，然后卡住不降；把学习率调小 10 倍，不震荡了，但降得极慢，最后停在一个比 6 层还差的地方。换初始化、换数据集、多跑几次——一样 💀。

这不是调参没调好，是那个结构在几十层的深度上就是这个表现。 原始论文用的是 6 层，这毛病在 6 层上几乎看不出来。

那一步归一化，站错了地方

先把两个词说清楚，后面全靠它们：

  • 残差：子层算完之后不是替换掉输入，而是加回到输入上——x + f(x)。这条「原样加回去」的路叫残差通路。
  • 归一化：把一组数字重新缩放到固定尺度（比如均值 0、方差 1），免得它们在几十层里越传越大或越传越小。

原始 Transformer 的一个子层是这么写的：

   Post-LN：  x_out = LayerNorm( x + Sublayer(x) )
                       ↑ 归一化套在最外面，把残差通路也一起归一化了

问题就出在「也一起」这三个字上。 回想 ResNet 里残差为什么有用——它给梯度开了一条加法通路：y = x + f(x) 求导得 1 + f'(x)，那个 1 保证梯度不被连乘吃光。

Post-LN 把这个 1 弄没了：x 先进了 LayerNorm 才输出。梯度回传时每穿一层就要过一次 LayerNorm 的雅可比矩阵——不再是「乘 1」，而是「乘一个跟当前激活尺度有关的量」。6 层连乘 6 次还行；96 层（GPT-3 的规模）连乘 96 次，靠近输入的层要么被压到近乎为 0、要么爆炸，而且各层尺度不一致，同一个学习率对某些层太大、对另一些层太小。

🔬 跑一遍：这个衰减确实随深度变糟

推理讲得通，但光讲得通不算数。把两种写法搭成同样的骨架、同样的初始化，回传一次，看最靠近输入的那层拿到多少梯度：

import torch, torch.nn as nn

def run(L, pre):                                   # L 层；pre=True 就是 Pre-LN
    torch.manual_seed(0)                           # ⭐ 两种写法的初始权重完全一样
    f  = nn.ModuleList([nn.Sequential(nn.Linear(256, 256), nn.GELU(), nn.Linear(256, 256)) for _ in range(L)])
    ln = nn.ModuleList([nn.LayerNorm(256) for _ in range(L)])
    x  = torch.randn(32, 256)
    for a, b in zip(f, ln):
        x = x + a(b(x)) if pre else b(x + a(x))    # ⭐ 全章最关键的一行：差别只在这里
    x.pow(2).mean().backward()
    return (f[-1][0].weight.grad.norm() / f[0][0].weight.grad.norm()).item()   # 末层 ÷ 首层

for L in (6, 12, 48, 96):
    print(f"{L:>3} 层   Post-LN {run(L, False):6.2f} 倍     Pre-LN {run(L, True):5.2f} 倍")
层数 Post-LN 首层梯度被衰减 Pre-LN
6 3.75 倍 0.94 倍
12 3.81 倍 0.87 倍
48 5.69 倍 0.74 倍
96 7.19 倍 0.60 倍

⭐ Post-LN 那一列随深度单调恶化（3.75 → 7.19）；Pre-LN 那一列不但不恶化，还小于 1——首层拿到的比末层还多，说明那条加法通路真的一路通到底。

⚠️ 它能证明什么、不能证明什么：随机初始化的玩具模型只跑了一次前后向，不是真实训练，7.19 倍谈不上「梯度消失」这种灾难。它能证明的只是趋势的方向和它随深度的走向；真实训练里这个偏差还会被优化器动量、几万步累积、各层尺度互不一致放大——那才是发散的来源。你的数值会和这里不同（换个种子就变），但两列的相对关系稳定。

warmup 治的是病，还是症状

这解释了第 9 章那句「大模型必配 warmup」的根源之一：Post-LN 头几百步各层激活尺度还很乱、梯度尺度也乱，此时学习率若已是满值，一步就能把某几层的权重推到再也回不来的地方——所以要先用极小的学习率「暖机」。

⚠️ 补丁的问题在于它掩盖了病因：warmup 长度成了必须精调的超参，调短了发散、调长了浪费算力，换个深度还要重调。你以为在调训练技巧，其实在补结构缺陷。

把归一化挪进分支里，主干就没人碰了

改法小到近乎可笑——把 LayerNorm 从括号外面挪到里面：

   Post-LN：  x_out = LayerNorm( x + Sublayer(x) )
   Pre-LN ：  x_out = x + Sublayer( LayerNorm(x) )
                      ↑ 主干上的 x 一路裸奔到顶，谁也没碰它

   展开 L 层： x_L = x_0 + f_1(LN(x_0)) + f_2(LN(x_1)) + … + f_L(LN(x_{L-1}))
             ⭐ 从输出到输入有一条【纯加法】的路，中间没有任何归一化

梯度沿这条路回到第 0 层时是完整的、没被缩放过的。这就是「梯度直通」——上表里 Pre-LN 那列小于 1，就是它。

现象 Post-LN Pre-LN
能堆多少层 十几层就开始难训 上百层没问题
需要 warmup 吗 必须，且长度敏感 可以短，甚至可以不要
学习率能开多大 小 大得多
同深度下的最终效果 略好 ⭐ 略差

⚠️ 别急着庆祝：96 层可能没有 96 层那么深

最后一行别跳过。 学界共识（也是面试常问的那个反直觉点）是：同等深度下，Post-LN 只要训得起来，效果通常比 Pre-LN 好一点。

为什么？「主干裸奔」有个副作用：主干一路长大，而每层往上加的东西尺度是固定的（分支的输入被归一化过）。越到深层，一层的贡献占主干的比例越小。这句话可以直接量出来——在 run(48, True) 的循环里把每层 a(b(x)) 的范数打出来：

主干 ‖x‖ 这一层加上去的 占比
第 0 层 90.72 18.46 20.3%
第 11 层 109.23 17.96 16.4%
第 23 层 127.59 17.95 14.1%
第 47 层 154.97 18.03 11.6%

⭐ 每层加上去的几乎不变（约 18），是主干自己长大了（90.72 → 154.97）。长法还有规律：这些分支输出彼此近似正交，主干按平方和累积——sqrt(90.72² + 48×18²) = 154.21，和实测的 154.97 几乎一致。即主干按 √层数 增长，单层的相对话语权按 1/√层数 衰减。

于是有了那个反直觉的结论：看着是 96 层，「有效深度」没那么深，行为上更接近一个更浅但更宽的模型。

⭐ 但在千亿参数尺度，这个权衡根本不用想： Post-LN 更好的前提是「它训得起来」。几千张卡跑几个月，一次发散可能回滚几天的进度。 稳定性的价值，远大于那一点点效果。 这就是 Pre-LN 全面胜出的真实原因。

💀 一个真实参照：Meta 训 OPT-175B 用了 992 张 A100 并公开了完整训练日志，里面记录了大量因 loss 发散、硬件故障导致的中断、回滚与临时超参调整——「训练过程需要人 7×24 盯着」是那个年代的常态。这正是后来所有人都换 Pre-LN、并叠一堆稳定性技巧的动机。 🔗 《AI基础设施》第 21 章整章在讲这件事。

💡 看代码时你一定会撞上的那个 final norm

Pre-LN 有个直接后果：最后一层的输出是从主干直接出来的，没经过任何归一化——而刚量过，主干尺度一路长到输入的 1.7 倍，层数越多越大，这样直接接输出层显然不行。

所以所有 Pre-LN 模型都会在 stack 最后补一个 final norm，代码里叫 model.norm（LLaMA）或 ln_f（GPT-2）。⭐ 看到一个孤零零挂在 stack 外面的 norm，别以为写错了——它是 Pre-LN 的必需品。

还有没有别的路：有，思路都是「既然残差通路被截断，就想办法把它接回来」。Sandwich-LN 在分支前后各来一个归一化；DeepNorm 在残差相加时给 x 乘一个跟深度有关的常数 α，让 Post-LN 也能堆到 1000 层——它证明了 Post-LN 的病可以对症下药治好，而不是这结构天生不行。主流仍是 Pre-LN，因为它最简单，而简单在千卡训练里本身就是价值。

🛑 读到这里可以停 —— 归一化的「站在哪」讲完了（约 30 分钟），刚好到全章一半。 你已经拿到：Post-LN 把残差通路截断了（实测 96 层时首层梯度衰减 7.19 倍，Pre-LN 只有 0.60）、改法不过是把 LN 从括号外挪进去、它不是纯赢（主干按 √层数 长大，深层的话语权被稀释）、以及 final norm 为什么非有不可。 后半章换一个问题：归一化的「是哪一种」——RMSNorm 砍掉了哪一步、为什么砍了效果不掉，以及一个反直觉的点：它 FLOPs 占比不到 1%，凭什么值得动。 回来的时候不用重读，直接从下一节接着看就行。

📏 四、有一步计算是白做的 —— 砍掉它，什么都没变差

现象：PyTorch 内置了 LayerNorm，为什么每个项目都自己手写一个 norm

回到开头那屏代码的第一行。nn.LayerNorm 是内置的、久经考验的算子，而几乎每一份现代 LLM 实现都绕过它，自己写十来行的 RMSNorm。自己造轮子通常是坏味道——能让所有人一起造同一个轮子的，一定有个够硬的理由。

先说清楚 LayerNorm 到底在干什么

它做的是三件事，不是一件：

   ① re-centering（再居中）：减去均值 μ      → 让这一行的均值变成 0
   ② re-scaling （再缩放） ：除以标准差 σ    → 让这一行的方差变成 1
   ③ 乘一个可学的 g，加一个可学的 b          → 允许模型把尺度再调回它想要的样子

（「一行」是哪一行：LayerNorm 是横着归一化，对一个 token 的所有特征维度做，不跨样本、不跨 token。🔗 第 10 章有那张 4×3 的对照图。）

RMSNorm 砍掉了第一步

$$\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}} \cdot g$$

变化只有两处：不减均值了，也不加 bias 了。分母从「标准差」变成「均方根 RMS」——两者的唯一区别就是标准差要先减均值。

砍掉了，效果为什么不掉

RMSNorm 论文（Zhang & Sennrich, 2019）的核心实验发现是：LayerNorm 真正起作用的是 re-scaling，不是 re-centering。 去掉减均值那步，效果基本不掉。直觉上：归一化在这里的职责是控制数值尺度、防止层层往上漂移，而这件事是除以 σ 干的；减 μ 管的是「平移」，后面紧跟的线性层本来就有平移能力（原本 LayerNorm 的 bias 也是干这个的，一并去掉了）。

⚠️ 别把这个结论推广得太远。 它是在 Transformer 这个特定结构里、后面紧跟线性层的经验结论，不是「所有归一化都可以不减均值」。

🔬 反直觉的一步：不到 1% 的 FLOPs，凭什么值得动

从 FLOPs 看，归一化在整个模型里占比极小（远不到 1%），砍掉一次减法看起来毫无意义。但这么想就错了，而且错得很典型。

⭐ 关键洞察：归一化是逐元素算子，瓶颈在显存带宽不在算力。 它要把整个激活张量从显存读出来、算一下、再写回去。GPU 的算力远远快于显存带宽， 所以这类算子的实际耗时，跟它读写了多少字节成正比，跟它算了多少次乘法几乎无关。 🔗 这正是《AI基础设施》第 4 章 Roofline讲的 memory-bound 区间。

在这个视角下收益就清楚了——省的不是那几次减法，是一整趟对张量的遍历：LayerNorm 要先遍历一遍求 μ、再遍历一遍求 σ（或用一趟算法但要多存中间量），RMSNorm 一趟就够，只需要平方和。而读写正是这个算子的全部成本所在。

论文报告的端到端加速在 7%~64% 之间。⚠️ 那个上限 64% 是特定小模型上的数字，别到处引用。现代大模型里的实际收益是个位数百分比——但它是白捡的（效果不掉、参数还更少），所以没有理由不换。这就是所有人一起造这个轮子的理由。

代码：十来行，外加两个必踩的坑

import torch, torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, dim: int, eps: float = 1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))   # ⭐ 只有缩放 g，没有 bias

    def forward(self, x):
        dtype = x.dtype
        x32 = x.float()                               # ⭐ 坑二：低精度下必须先升到 fp32
        rms = torch.rsqrt(x32.pow(2).mean(-1, keepdim=True) + self.eps)  # ⭐ 坑一：eps 在开方【里面】
        return (x32 * rms).to(dtype) * self.weight

h = torch.randn(2, 5, 8)
print(nn.LayerNorm(8)(h).shape, RMSNorm(8)(h).shape)        # 形状一样，可以直接替换

zero = torch.zeros(1, 8)                                     # 坑一现场
print(zero / zero.pow(2).mean(-1, keepdim=True).sqrt())      # [nan, …] 💀 eps 漏了
print(torch.full((1, 8), 300.0, dtype=torch.float16).pow(2).mean(-1))  # inf 💀 坑二现场
坑 后果
eps 加在开方外面（或忘了加） 整行接近 0 时分母炸掉出 NaN（上面第二个 print 就是现场）。必须写成 sqrt(mean(x²) + eps) 而不是 sqrt(mean(x²)) + eps
fp16/bf16 下直接算平方和 300 这个再普通不过的激活值，平方后是 90000，已超出 fp16 上限 65504，直接变 inf。正经实现都先 .float() 再算，最后转回去

⚠️ 两个坑都平时不发作：小模型、fp32、正常数据下一切正常，等上了 bf16 混合精度、跑到几万步遇到一个异常样本才炸——而那时 loss 已经是 NaN，你要从头找。

到这里，开头那屏代码你已经能读懂一半：class RMSNorm 和 self.input_layernorm(x) 都不再是谜。剩下两行——apply_rotary_emb 和那个三矩阵相乘的 FFN——归 02e，也正是上面那张 config 表里 intermediate_size 和 rope_theta 两行的「为什么」。

✅ 检查点

  1. 拿到一个陌生模型的 config.json，哪个字段一出现就说明用的是 RMSNorm？怎么用两个字段的比值判断它是不是 SwiGLU 家族？
  2. Post-LN 和 Pre-LN 的公式分别怎么写？为什么说 Post-LN「把残差的那个 1 弄没了」，这跟层数有什么关系？
  3. 本章那个梯度实验，96 层时两种写法的首层衰减分别是多少倍？这个实验不能证明什么？
  4. warmup 为什么被说成「补丁而不是解法」？它掩盖的病因是什么？
  5. Pre-LN 是纯赢吗？「96 层没有 96 层那么深」是什么意思，本章用什么数据支持它？
  6. 为什么 Pre-LN 模型必须在 stack 最后补一个 final norm？代码里它通常叫什么名字？
  7. RMSNorm 相比 LayerNorm 去掉了哪两样东西？为什么去掉也没事？
  8. 归一化 FLOPs 占比不到 1%，为什么换成 RMSNorm 还是有意义？实现上有哪两个坑，为什么特别难发现？
👀 答案
  1. rms_norm_eps——光是这个字段名出现就说明是 RMSNorm。判 SwiGLU 看 intermediate_size / hidden_size：约 2.67（即 8/3）→ SwiGLU 家族；约 4.0 → 老式两矩阵 FFN。LLaMA-7B 是 11008 / 4096 = 2.6875。
  2. Post-LN：LayerNorm(x + Sublayer(x))；Pre-LN：x + Sublayer(LayerNorm(x))——差别只是把 LayerNorm 从括号外面挪到了里面。残差 y = x + f(x) 求导得 1 + f'(x)，那个 1 保证梯度不被连乘吃光；Post-LN 里 x 先进了 LayerNorm 才输出，于是梯度每穿一层都要乘一次 LayerNorm 的雅可比而不是乘 1。层数越多连乘越多：6 层还行，96 层连乘 96 次，靠近输入的层要么压到近 0 要么爆炸；各层尺度还不一致，同一个学习率对某些层太大、对另一些太小。
  3. Post-LN 衰减 7.19 倍，Pre-LN 0.60 倍（小于 1 = 首层拿到的比末层还多）；Post-LN 那列随深度单调恶化（3.75 → 7.19）。⚠️ 不能证明的：随机初始化的玩具模型、只跑一次前后向，不是真实训练，7.19 倍谈不上「梯度消失」这种灾难——它只能证明趋势的方向和它随深度的走向。
  4. 病因是 Post-LN 把残差通路截断了、各层梯度尺度不一致。warmup 只是用「前期学习率极小」躲过最危险的阶段，结构没修。代价是 warmup 长度成了敏感超参：调短了发散、调长了浪费算力，换个深度就要重调。
  5. 不是纯赢——同等深度下 Post-LN 只要训得起来，效果通常略好。「有效深度不足」指主干一路长大而每层加上去的尺度固定，越深层贡献占比越小。实测 48 层：每层都约 18，主干 90.72 → 154.97，占比 20.3% → 11.6%；主干按平方和累积（sqrt(90.72² + 48×18²) = 154.21，与实测吻合），即按 √层数 长、话语权按 1/√层数 掉。但仍全选 Pre-LN：前提是「它训得起来」，千卡上一次发散回滚几天，稳定性的价值远大于那点效果。
  6. 因为 Pre-LN 末层输出是从主干直接出来的、没经过任何归一化，而主干尺度一路长大（实测约到输入的 1.7 倍，层数越多越大），直接接输出层不行。代码里叫 model.norm（LLaMA）或 ln_f（GPT-2）。
  7. 去掉了减均值（re-centering）和 bias。因为 LayerNorm 起作用的主要是 re-scaling（控制数值尺度），平移这件事后面紧跟的线性层本来就能做。⚠️ 这是 Transformer 这个特定结构里的经验结论，别推广到所有归一化。
  8. 因为归一化是逐元素算子，瓶颈在显存带宽不在算力（memory-bound）——耗时跟读写多少字节成正比，跟算多少次乘法几乎无关。LayerNorm 要遍历张量两次（先 μ 后 σ），RMSNorm 一趟就够。论文报 7%~64% 加速（上限是特定小模型的数字），现代大模型上是个位数，但效果不掉、参数还更少，白捡。两个坑：① eps 必须放在开方里面，否则接近全 0 的一行出 NaN；② fp16/bf16 下必须先 .float() 再算平方和（300 平方后是 90000，超过 fp16 上限 65504，直接 inf）。难发现是因为两个都平时不发作——小模型、fp32 下一切正常，等上了混合精度、几万步后遇到异常样本才炸，而那时 loss 已经是 NaN。

⚡ 走神救援

骨架一行没改，只换了四个零件；本章是长在「归一化」上、互相咬合的前两处。⭐config 表最快能用：rms_norm_eps 一出现就是 RMSNorm；intermediate_size / hidden_size ≈ 2.67 是 SwiGLU 家族、≈ 4.0 是老式 FFN。①Post-LN → Pre-LN：现象是层数从 6 加到 48，loss 震荡后卡住不降，调小学习率也救不回来。病因——Post-LN 写成 LN(x + f(x))，归一化套在最外面把残差通路也一起归一化了：残差本靠 1 + f'(x) 那个 1 保梯度，现在每穿一层都要乘一次 LayerNorm 的雅可比，96 层连乘就消失或爆炸。实跑：Post-LN 首层梯度衰减 6 层 3.75 倍 → 96 层 7.19 倍，Pre-LN 0.60 倍（⚠️ 玩具模型只跑一次前后向，只能证明趋势方向）。warmup 只是补丁，病因没修、换深度就要重调。改法小到可笑：把 LN 从括号外挪进去，x + f(LN(x))，展开成 x_L = x_0 + Σf_i(LN(x_i))，一条纯加法的路，梯度直通。⚠️不是纯赢：同深度下 Post-LN 训得起来的话效果略好——主干在长大而每层加上去的尺度固定，实测每层都约 18、主干 90.72 → 154.97、占比 20.3% → 11.6%，即按 √层数 长、话语权按 1/√层数 掉，所以「96 层没有 96 层那么深」。仍全选 Pre-LN：「效果好」的前提是「训得起来」，千卡上一次发散回滚几天（OPT-175B 用 992 张 A100，公开日志全是发散与回滚）。⭐ 主干末端没归一化又长到约 1.7 倍，所以 stack 最后必须补一个 final norm（model.norm / ln_f）。旁支有 Sandwich-LN 和 DeepNorm（给 x 乘个跟深度有关的 α，让 Post-LN 也能堆到 1000 层）。②LayerNorm → RMSNorm：只砍掉减均值和 bias——因为起作用的是 re-scaling 不是 re-centering（Zhang & Sennrich 2019），平移后面的线性层本来就能做。⭐反直觉：它 FLOPs 不到 1%，凭什么值得动？因为是逐元素算子、memory-bound，耗时跟读写字节成正比、跟乘法次数几乎无关——LN 要遍历两趟，RMSNorm 一趟就够（论文报 7%~64%，现代大模型上个位数，但白捡）。⚠️ 两个坑都平时不发作、上混合精度几万步后才炸：eps 必须在开方里面、fp16 下必须先 .float() 再算平方和（300² = 90000 > 上限 65504，直接 inf）。
