## 它和别的教程有什么不一样

大多数教程假设你能连续专注两小时，并且中断之后能自己接上。这套不这么假设。
每一章都带五个固定零件，**它们不是排版装饰，每一个都在解决一个具体的中断问题**：

| 零件 | 解决的问题 |
|---|---|
| ⏱ **时间徽章** | 「现在这段空档够不够读完」——所以它必须准。全站按 **170 字/分钟**统一量过，**宁可多报不少报**：标 30 分钟实际 80 分钟，人会中途弃坑，而且从此不再信这个数字 |
| 🎯 **一句话** | 全章压成一句。**只看这一句就走，是被允许的** |
| 🛑 **可以停在这里** | 明确的退出点。超过 55 分钟的章还会在中间插一个断点——**「停在这里」比「读不完的愧疚感」重要** |
| ⚡ **走神救援** | ⭐ 最特别的一个。全章要点压成一段、带具体数字，**隔几天回来只读这一段就能接上**，不用重读整章 |
| ✅ **检查点** | 6–10 题 + 折叠答案，只问正文真讲过的东西 |

另外：⭐ 是重点，⚠️ 是坑，💀 是**真出过事**的例子（写清发生了什么、为什么没被发现、代价多少）。

## 仓库结构

```
index.html          总目录（站点首页）
<板块名>/           15 个板块，每个目录下是该板块的章节 HTML
assets/             字体等静态资源
_src/               ⭐ 源：13 个 *_md/ 目录（markdown 正文）+ 105 个构建与校验脚本
CLAUDE.md           交接文档 —— 想改内容或加板块，先读它
```

### 想改内容

⚠️ **有 md 源的板块请改 `_src/<板块>_md/` 下的 markdown，不要直接改 HTML**——
构建会用 md 重新生成 HTML，直接改的 HTML 一构建就没了。

```bash
cd _src
python build_all.py          # 一条命令构建全站（含图例注入）
```

改完建议跑一遍校验（每个脚本查一类问题，都在 `_src/` 下）：

```bash
python verify_links.py          # 全站链接
python check_svg_all.py         # 内联 SVG 六项体检
python check_details_render.py  # 折叠块里的 markdown 有没有真被渲染
python check_nextlink.py        # 章尾「下一节」链条和构建器顺序是否一致
python audit2.py                # ADHD 结构要素是否齐全
python fix_time.py              # ⏱ 徽章校准
```

⚠️ **`Kaggle竞赛方法论` / `Claude博客资料库` 两个板块没有 md 源，`推荐算法` 只有 `15b` 一章有**——
对这几个直接改 HTML 才是正确做法，不会被构建覆盖。
详见 `CLAUDE.md` 第二节「四条会让你白干的规则」。

## 内容口径

- **时间徽章按 170 字/分钟统一量过**，改完内容跑 `fix_time.py` 重新校准，不靠手写
- **代码块每段自带 import，复制到空文件就能跑**；跑不了的（需要数据库 / 真实 API / 浏览器）会明确标注 `🗓️ 未实跑`
- **性能数字都是实跑出来的**，不是估的；跨机器会有差异的地方会写明「你的数值会不同」
- **🗓️ 标记表示这块内容会过期**（框架 API、平台控制台路径、价格），用前请查最新文档
