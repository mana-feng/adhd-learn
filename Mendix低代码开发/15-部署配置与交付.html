15 · 把应用交到别人手里

⏱ 阅读约 11 分钟 ｜ Studio Pro 11.12 LTS，动手时间另计

🎯 一句话

交付包含可追溯的版本、正确的环境配置和可恢复的数据。 自己电脑能打开应用，只完成了本地运行。

起点：权限、审批与失败路径已在自己的应用核验。本章选择 Mendix Cloud 路线；环境与发布权限以实际套餐为准，免费环境不等于完整生产环境。

🧩 一、四种材料分别记录

材料 解决什么问题 本例记录
应用源与版本库 谁改了什么 分支、提交、11.12.x 补丁号
部署包 实际运行什么模型 包版本、构建来源、验收结果
环境配置 各环境连接哪里 接口地址、凭据、计划任务
数据与文件备份 发生故障后恢复什么 备份时间、内容、对应模型

模块 .mpk、应用源包和 .mda 部署包用途不同。同事继续建模需要源，运行环境需要部署包，恢复业务还需要数据库与文件。

🔐 二、把配置移出个人电脑

第 12 章的 AssetApiBaseUrl 在本地使用回环地址，测试要换成测试服务，生产使用正式服务。ApiToken 作为服务端配置默认留空，真实值由环境管理提供，不提交到版本库。

密钥常量的 Exposed to client 关闭；这不意味着常量自动提供完整密钥管理，环境管理员也应按职责控制访问。常量属性

生产停用演示账号，不沿用测试密码。Security 的 Production 级别只是模型安全设置，不代表已经上线。初始化测试数据入口也要受管理员权限和环境限制。

另列部署包之外的材料：Excel 模板数据、证书、模块角色映射、计划事件和外部服务配置。新环境不一定有你本地数据库里的模板，上传包后逐项检查。

🛠️ 三、同一版本先进入测试环境

团队统一准确的 11.12 补丁号。模型一致性检查无错误后提交源改动，记下提交标识；不要一人升级模型，另一人仍用旧编辑器保存。

从 Studio Pro 的 App > Create Deployment Package 建包，或在 Portal 的 Deployment Packages 中从指定分支和提交构建。给包写版本及变更说明，不用不同源反复生成同名包。官方部署步骤

选择测试环境，核对名称与地址，补齐常量后部署启动。查看启动日志，再打开应用。用独立账号完成下列路径：

  1. 提交人建立 500 元工单，直接进入待接单。
  2. 新建 501 元工单，主管完成待办，处理人接单并关闭。
  3. 另一提交人不能读取前者工单或下载附件。
  4. 外部接口失效时反馈明确，查询不改变工单状态。
  5. 重新登录后工单、附件和任务历史仍可读。

页面打卡不连接实际应用，这些项目需要你亲自执行并记录。无目标环境时标记未测，不写为通过。

💾 四、上线之前先做一次恢复

确认备份包含数据库和文件，记录备份时刻以及当时部署包。在单独的测试恢复环境演练，避免覆盖正在使用的环境。

恢复后核对同一张工单的字段、审批历史、附件内容与访问权限。只有数据库行还在，不代表图片文件恢复了。检查环境地址和凭据，避免恢复出的测试环境连到正式外部服务。

恢复入口与条件见Cloud 备份恢复。模型要与数据相容；回退旧包不会自动撤销数据迁移，更不会撤销已经发送到外部系统的动作。

用业务语言写清“最多允许丢多久数据”和“允许多久恢复”，再对照演练结果确定备份间隔与恢复步骤。没有演练的数字不能当成已经具备的能力。

中途停靠： 从测试备份恢复一张带附件、带审批历史的工单，就得到一条可交接证据。

🧭 五、上线及后续观察

发布记录写明发布人、目标环境、包、备份、维护窗口及回退条件。发布测试通过的同一部署包，环境差异通过配置管理；迁移与回退策略在执行前确定。

上线后观察启动异常、接口错误比例、响应时间、队列积压和 Workflow 失败实例。阈值基于业务与测试基线；没有红色日志不等于用户能报修，仍要走一条明确标记的验收工单。

发生失败先区分错误配置、版本缺陷和数据迁移问题。修正地址可能足够；恢复备份会影响之后新增的数据，应按既定方案执行，不能随手点击试试。

🤝 六、多人协作按模型对象分工

先约定各自负责的模块、页面、流程和共享实体。合并前更新本地、检查 Changes，再处理模型冲突；不要批量选择自己的版本覆盖同伴。

合并后核对关联、枚举、页面参数、角色映射和已有流程实例的兼容性。冲突窗口关闭只是选择完成，业务关系是否仍正确还要复验。

✅ 检查点

  1. Production 安全级别等于上线吗？
  2. 为何发布同一部署包？
  3. 回退包会恢复数据吗？
  4. 只核对数据库行够吗？
查看答案
  1. 不等于，只是模型安全设置。
  2. 确保运行模型和已验收模型一致，环境差异由配置管理。
  3. 不会，数据库、文件、迁移与外部副作用需独立恢复方案。
  4. 还要核对文件内容、权限和流程历史。
