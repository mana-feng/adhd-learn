20 · Java 与 JavaScript 扩展

⏱ 阅读约 11 分钟 ｜ Studio Pro 11.12 LTS，动手时间另计

🎯 一句话

代码扩展是一项有输入输出的能力，业务权限和状态规则仍由应用明确控制。 先写一个不依赖页面的纯函数，再把它接到可视化流程里。

起点：理解 Microflow 与 Nanoflow。Java action 在服务端被 Microflow 调用；JavaScript action 在客户端被 Nanoflow 调用。两者不是同一语言，也不能直接互换。

🧩 一、按执行位置选择扩展

需求 首选位置 本例边界
格式化输入、使用浏览器能力 JavaScript action / Nanoflow 不保存密钥，不决定权限
使用服务端 Java 库或计算 Java action / Microflow 输入明确，异常可处理
普通字符串判断和状态分支 现有表达式与 Microflow 不必为了“写代码”增加依赖

本章的标题规范化通常用表达式也能完成，刻意选这个小函数是为了练习扩展边界。输出仅是建议，不替用户悄悄改写报修内容。

🧪 二、先在应用外验证纯函数

目标是：去掉首尾空白，把连续空白缩成一个空格，保留中文及标点。下面是完整 JavaScript，可保存为 normalize-title.mjs 后用 node normalize-title.mjs 执行；也提供可下载版本。需先安装 Node.js。

function normalizeTitle(input) {
    if (typeof input !== 'string') {
        throw new TypeError('标题必须是字符串');
    }
    return input.trim().replace(/\s+/gu, ' ');
}

const cases = [
    ['  投影仪   不亮  ', '投影仪 不亮'],
    ['\t门锁\n故障', '门锁 故障'],
    ['   ', ''],
];
for (const [input, expected] of cases) {
    const actual = normalizeTitle(input);
    if (actual !== expected) throw new Error('规范化结果不符合预期');
    console.log(actual === '' ? '空字符串' : actual);
}

第 2—4 行限定输入类型；第 5 行把全部空白序列压成一个空格。空白标题输出仍为空，不会自动变成“未命名工单”；有效性由第 11 章的提交检查决定。

运行时应依次看到“投影仪 不亮”“门锁 故障”“空字符串”。独立脚本验证只覆盖字符串函数，不证明 Mendix 页面已经正确接线。

🛠️ 三、接成 JavaScript action

在 Helpdesk 新建 JavaScript action NormalizeTitle，参数 input 为 String，返回 String。11.12 提供正式可用的新 JavaScript 编辑器；生成文件位于应用的 javascriptsource 下模块 actions 目录。官方 JavaScript action 说明

把上面的 normalizeTitle 函数放进生成文件的 EXTRA CODE 保留区；在 NormalizeTitle 的 USER CODE 保留区返回 normalizeTitle(input)。不要复制下面的测试循环到动作里，也不要删除生成器需要的导出函数与参数签名。生成器保留区之外的改动可能在重新生成时丢失。

建立 ACT_WorkOrder_PreviewTitle Nanoflow，参数为当前草稿 WorkOrder。调用 NormalizeTitle，input 传 Title，结果放 String 变量；用 Show message 展示建议即可。此步不 Commit，不直接修改 Status，也不调用 Workflow。

用同一组输入通过页面触发，核对与独立脚本一致。动作抛错时通过 Nanoflow 错误路径显示失败，不把空结果当成成功标题。

中途停靠： 应用外函数和页面调用给出一致结果，就完成一次代码能力接入。

☕ 四、用同样契约理解 Java action

准备适配所选 Studio Pro 11.12 补丁的开发 JDK，优先用安装器和官方系统要求指定的版本。不要从网上随便装一个 JDK 后用“能编译”代替兼容性核对。

在 Helpdesk 新建 Java action NormalizeTitleServer，参数 Input String，返回 String，生成 Java 源。找到 javasource 下模块 actions 文件，保留类、构造器和生成的参数字段；仅在 executeAction 的 USER CODE 区实现处理，在 EXTRA CODE 区放必要辅助函数。

Java 的具体输入字段名以生成器为准。本例先判断 Input 是否为 null，空值抛出清楚的参数异常；否则使用 String 的 strip 与 replaceAll 处理首尾和连续空白。Java 正则的 Unicode 空白与 JavaScript 不一定完全一致，补测全角空格和不换行空格，不先承诺两端对所有字符等价。

创建测试 Microflow 调用该 Java action，输入固定“ 投影仪 不亮 ”，输出 String 并显示。重新运行应用以编译 Java，查看首个编译错误；别修改 deployment 中的临时产物来消除它。生成和保留区规则见官方 Java 扩展教程。

真正复用第三方 Java 库时，记录版本、许可、依赖和打包方式；冲突先核对依赖来源，不能把 userlib 的所有 jar 删除再试。

🔎 五、分别验收函数、动作与业务

函数层检查普通中文、空串、异常输入与 Unicode 空白；动作层检查参数、返回值、异常路径和重新生成后代码保留；业务层检查用户仍只能处理自己有权操作的工单。

客户端同样的函数不能成为服务端信任依据。即使浏览器已经把标题规范化，服务端仍执行提交校验。扩展只扩大能力，不缩小已有权限边界。

✅ 检查点

  1. JavaScript action 从哪里调用？
  2. 纯函数测试通过证明页面接好了吗？
  3. 代码放生成文件哪里？
  4. 空白标题规范化后可以提交吗？
查看答案
  1. Nanoflow，在客户端运行；Java action 由 Microflow 在服务端调用。
  2. 不证明，还要测试参数、返回值和页面触发。
  3. 对应 USER CODE/EXTRA CODE 保留区，保留生成签名。
  4. 输出为空，仍应被业务提交校验拒绝。
