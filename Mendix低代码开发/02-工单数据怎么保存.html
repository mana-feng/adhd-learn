02 · 工单数据怎么保存

⏱ 阅读约 9 分钟 ｜ 动手可分为字段与页面两个阶段

🎯 一句话

Entity 是一类数据的定义，Object 是按这个定义创建的一份具体数据。 先给工单定义字段，下一章再创建真正的工单。

起点： 第 01 章的 HelpdeskLearning 应用，已有 Helpdesk 业务模块，能本地运行。

🧩 一、先把一句报修拆开

“会议室投影仪不亮，预计维修 300 元，目前还没有提交。”这句话至少包含标题、描述、预计费用和状态。把它们分开后，应用才能按状态筛选、按费用判断，而不必猜一句自然语言的意思。

概念 在本例中是什么 不是什么
Entity（实体） WorkOrder，定义每张工单有哪些字段 不是某一张工单
Attribute（属性） Title、EstimatedCost 不是页面上的一个输入框
Object（对象） 标题为“投影仪不亮”的这一张工单 不是整张数据库表
Enumeration（枚举） 一组允许使用的状态值 不是让人任意输入的字符串

页面输入框负责展示和编辑属性。同一个属性可以出现在列表页和详情页，不需要因此再建两份字段。

🛠️ 二、建立 WorkOrder

在 App Explorer 打开 Helpdesk > Domain model，从 Toolbox 添加一个 Entity，命名 WorkOrder，保持 Persistable 为 Yes。双击实体，在 Attributes 中新增下列属性。

Name Type 本教程设置 例子
Title String 长度 120 投影仪不亮
Description String Unlimited 指示灯亮，但没有画面
EstimatedCost Decimal 默认 0 300.00
Resolution String Unlimited 更换连接线后恢复

金额使用 Decimal，是为了按十进制金额表达业务规则。这里只演示单一币种；需要多币种时必须额外保存币种及换算规则，不能把不同币种直接求和。

在 Helpdesk 模块中新建 Enumeration，命名 ENUM_WorkOrderStatus，加入下列 Name 和 Caption，再回到 WorkOrder 添加 Status 属性，类型选择这个枚举，默认值选择 Draft。

Name（逻辑用） Caption（用户看）
Draft 草稿
Submitted 已提交
InProgress 处理中
Closed 已关闭

例如表达式中使用 Helpdesk.ENUM_WorkOrderStatus.Draft，页面可以显示“草稿”。名称与显示文字分开，可以调整界面文案而不把业务规则一起改掉。

🔍 三、保存模型还没有产生工单

保存并重新运行后，Runtime 会根据模型处理所需的数据结构。这一步创建的是存储结构，不是那张“投影仪不亮”的记录。 你还需要从页面或逻辑中创建对象，再保存数据。

现在检查实体属性是否与表格一致：尤其是 EstimatedCost 的类型、Status 的枚举及默认值、WorkOrder 的 Persistable。下一章页面选择这些字段时，拼错的名称会立刻暴露。

官方领域模型配置说明解释实体、属性和关联怎样组成数据层。这里先只做一个实体；关系在第 04 章集中完成。

🧪 四、用反例检查设计

如果 Status 用普通 String，用户可能填出“已提交”“已提 交”“提交了”三个值。筛选器需要不断补例外。用枚举后，用户只能在定义好的状态中选择。

但枚举只限制“值来自哪个集合”，不会自动限制“草稿能否直接变成已关闭”。状态之间允许怎样变化，是第 09 章逻辑要完成的工作。

同样，属性长度不是完整的业务校验。120 字符的 Title 仍然可能是空白；第 05 章会在提交动作中验证标题。

✅ 检查点

  1. 新建 WorkOrder 实体后，是否已经有一张工单？
  2. 为什么状态用枚举，而描述用 String？
  3. 枚举中有 Closed，是否意味着任意用户都能关闭工单？
查看答案
  1. 没有。实体是定义，还需要创建并保存具体对象。
  2. 状态属于可列举的有限选项；描述需要自由表达问题。
  3. 不是。枚举不提供操作授权，权限与状态转换需要另外配置。
