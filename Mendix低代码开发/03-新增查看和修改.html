03 · 让用户能新增、查看和修改

⏱ 阅读约 9 分钟 ｜ 先完成一次保存，再做其他操作

🎯 一句话

列表显示一组对象，编辑页接收一个对象；页面参数把这两处连接起来。 本章先做本机练习版，完整权限会在第 08 章加入。

起点： WorkOrder 已有 Title、Description、EstimatedCost、Resolution、Status 五个字段；枚举和默认值与第 02 章一致。

🪟 一、生成页面后先认数据来源

在 Domain model 中右击 WorkOrder，使用 Generate overview pages（生成概览页）入口，选择适合 Web 的概览与编辑模板。把生成的业务页面命名为 WorkOrder_Overview 和 WorkOrder_NewEdit。模板若没有自动生成编辑页，可新建页面并放入 Data view，数据源选择 WorkOrder 页面参数。

不要只看“生成了两个页面”。逐项核对下面的连接：

位置 必须连接到哪里 原因
概览页列表或网格 WorkOrder 数据源 才能列出已保存的工单
新建按钮 创建 WorkOrder，打开编辑页 编辑页需要一个新对象
编辑按钮或行操作 当前选中 WorkOrder，打开编辑页 修改的必须是选中的那一张
编辑页 Data view WorkOrder 页面参数 输入框要知道编辑哪个对象
Title 输入框 当前对象的 Title 显示文本不是独立数据副本

不同模板可能生成 Data grid 2 或其他列表控件。选择控件后在 Properties 核对数据源，不把模板外观当作数据绑定成功的证据。关于容器和数据源参见官方 Data View 文档。

🧭 二、加一个真的能到达的入口

打开 App 的 Navigation，在当前 Web 导航菜单中添加“工单”，目标设为 WorkOrder_Overview。保存并运行，通过导航菜单进入概览页。

编辑页暂时只保留 Title、Description、EstimatedCost，以及显示为只读的 Status。隐藏 Resolution 输入，它属于处理阶段。不要让读者在“新增工单”时就猜如何关闭它。

保留模板生成的 Save changes 和 Cancel changes 按钮，分别确认它们执行保存与取消，而不只是 Close page。单独关闭页面不等于撤销数据修改。

🧪 三、完成一轮可观察的验证

  1. 点击新增，标题填“会议室投影仪不亮”，描述填“指示灯亮但无画面”，费用填 300，然后保存。
  2. 回到概览页，应该看到这条记录；状态应为“草稿”。
  3. 重新打开该记录，把费用改为 350，保存，再次打开确认是 350。
  4. 把标题改为“取消测试”，点击 Cancel changes，再重新打开，确认标题仍是原来的内容。
  5. 刷新浏览器，重新进入列表，确认已保存记录仍然存在。

这些都是预期结果。某一步不一致就停在该步排查，不必为了追进度继续建第二张页面。

完成之后，再用一张可丢弃的测试记录试删除。当前阶段可以保留生成的删除按钮；第 08 章会移除提交人直接删除工单的能力。真实工单通常需要留痕，不应随手删除。

🩹 四、用现象找连接错误

现象 优先检查
页面要求参数，菜单却直接打开它 菜单应打开概览页；编辑页需要具体 WorkOrder
保存后列表没有新记录 保存动作是否提交、列表是否检索相同实体、是否有筛选
每次编辑都变成新增 编辑按钮是不是错误地执行了 Create object
取消后数据仍被保存 中间是否已经调用其他提交逻辑；取消不是历史撤销

一张页面可以正确显示，但绑定了错误的对象。用两张标题不同的记录分别编辑，比只测试一张更容易发现这种问题。

✅ 检查点

  1. 为什么概览页适合放到导航中，而编辑页不能总是直接打开？
  2. 编辑按钮把当前对象传给页面，和创建新对象有什么差别？
  3. 单独刷新页面能证明 Cancel changes 工作正确吗？
查看答案
  1. 概览页可检索对象列表；编辑页需要先知道编辑哪个 WorkOrder。
  2. 前者修改原记录，后者会产生另一份对象，可能保存为新记录。
  3. 不能。应该先修改、取消、重新打开同一条记录，观察原值是否保留。
