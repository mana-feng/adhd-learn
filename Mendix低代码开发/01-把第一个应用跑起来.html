01 · 把第一个应用跑起来

⏱ 阅读约 8 分钟 ｜ 安装和下载时间取决于网络

🎯 一句话

先让一个页面在浏览器里打开，再逐项增加业务内容。 本章的成功标志是本地应用运行，并且页面能显示你自己修改的文字。

起点： Windows 电脑、可用网络、Mendix 账号。已有项目也可以跟做，但先备份，并确认它使用的 Studio Pro 版本。本章不替你升级已有项目。

🧰 一、准备相同的运行环境

  1. 从官方安装入口进入 Studio Pro 下载页，选择 11.12 LTS 的补丁版本，记录完整版本号。
  2. 按安装器提示安装依赖。不要凭旧教程自行拼装 Java 或 .NET 版本；开发环境依赖按安装器和 11.12 对应文档处理。
  3. 启动 Studio Pro，登录自己的 Mendix 账号。若登录或组件下载失败，先核对代理和企业网络设置。
  4. 建立一个用于学习的项目目录。不要把真实业务数据、生产密钥或同事的项目混到本练习里。

安装要求会随补丁变化，具体依赖和网络端点以11.x 系统要求及 11.12 发布说明为准。这里不要求你背硬件参数，只要能稳定打开编辑器、完成构建并运行本地应用。

🏁 二、创建空白应用

在新建应用入口选择兼容当前版本的空白 Web 应用模板，命名为 HelpdeskLearning。保留模板带来的 Administration、Atlas 等基础模块；模板菜单与可用选项可能随版本变化，以“空白、Web、兼容 11.12”为选择条件。使用模板提供的 Web 客户端配置，后续选控件时也核对它支持当前客户端。

在 App Explorer 中找到业务模块。可以把默认业务模块改名为 Helpdesk，也可以新建这个模块，把本教程新增的页面、枚举、Microflow 和 Workflow 都放在其中。不要重命名 System 或 Marketplace 模块来凑命名。

这里容易混淆： HelpdeskLearning 是整个应用；Helpdesk 是应用内的业务模块。网站上的“Mendix 教程板块”又是另一件事。

编辑器里的区域 本章用来做什么
App Explorer 找页面、模块、Navigation 和 Security
中间编辑区 修改当前打开的页面或模型
Toolbox 搜索可以放到当前编辑器中的元素
Properties 设置选中元素的属性
Errors / Console 查看模型错误和运行日志

▶ 三、运行并证明改动已生效

  1. 在 App 的 Navigation 中找到默认首页，打开它。在页面中添加一段 Text，填写“我的报修工作台”。
  2. 保存，然后使用 Run locally。如果 Errors 里有一致性错误，先双击第一条错误定位并修复；不要跳过它去刷新浏览器。
  3. 运行成功后使用 View App。由编辑器打开本地地址，避免自己猜端口。
  4. 在浏览器确认出现“我的报修工作台”。再改为“报修工作台 · 练习”，保存并重新运行，确认第二次修改也出现。

预期结果： 浏览器显示第二段文字。这个往返证明“你正在编辑的项目”和“你正在看的应用”确实对应。它还不证明数据库保存、权限或部署完成。

🩹 四、没打开时只追一条线索

现象 先查什么 下一步
Run 前已有红色错误 Errors 的第一条一致性错误 双击定位缺失引用或错误属性
运行启动失败 Console 的启动错误 按错误检查依赖、端口或配置
浏览器无法连接 应用是否仍在运行 回 Studio Pro 查看运行状态，再用 View App
仍显示旧文字 打开的项目和地址是否正确 重新运行，再刷新当前应用页面

记录完整错误信息和出现步骤。不要在没有线索时同时重装软件、改端口、换模板；一次改变一个因素，才知道哪一步有效。

✅ 检查点

  1. “项目已保存”和“浏览器里的应用已更新”是一回事吗？
  2. HelpdeskLearning 与 Helpdesk 分别是什么？
  3. 页面打开了，能否直接认为多人权限也正确？
查看答案
  1. 不是。还要运行对应项目并观察浏览器里的修改。
  2. 前者是应用名，后者是其中放业务模型和页面的模块。
  3. 不能。身份和数据权限在第 08 章单独配置、单独测试。
