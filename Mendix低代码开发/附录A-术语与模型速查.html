🎯 一句话

先确定正在操作的是定义、对象、任务还是一次请求，再找对应属性。 本页按教程实际用法查阅，不需要背完再开始。

📚 一、数据与页面

英文 本教程含义 回看
Domain Model 实体、属性与关联组成的数据模型 04
Entity / Object 类型定义 / 该类型的一个具体对象 02
Attribute 对象的一个值，如 Title 02
Association 对象之间的关系，如提交人 04
Persistable 可持久保存到数据库的实体 06
Non-persistable 运行时临时对象，如接口响应 12
Generalization 继承父实体成员，如附件继承 FileDocument 13
Data view 围绕一个对象显示或编辑内容 03
Data source 页面或列表从哪里取得数据 07
Enumeration 一组明确命名的可选值 09

“这张工单不见了”先判断是对象没存、筛选没匹配，还是当前人无权读取。不能只从页面空白推断数据被删除。

⚙️ 二、逻辑与权限

英文 当前含义 容易混淆的边界
Microflow 服务端逻辑 一次调用不等于整个跨人审批
Nanoflow 客户端逻辑 检查通过不代表获得授权
Commit / Rollback 提交对象 / 撤销相关改变 数据库事务和页面刷新分别理解
Retrieve / XPath 取得对象 / 描述查询约束 从关联查询不等于不受权限影响
App role / Module role 应用角色 / 模块角色 要配置映射，名称相同不会自动绑定
Entity access 对象与成员访问规则 页面隐藏不能替代服务端数据权限
Apply entity access Microflow 是否应用实体访问 关闭后要明确核验每条特权操作
Validation feedback 定位字段的错误提示 对象和成员必须与控件绑定一致

本教程 ACT、SUB、VAL 是命名约定：分别帮助辨识业务入口、子逻辑与校验，不是平台自动识别的安全机制。

🧭 三、Workflow 的四个层次

名称 是什么 本例
Workflow definition 流程定义 WF_WorkOrderApproval
Workflow instance 某次流程的运行记录 某张 501 元工单的审批实例
Workflow context 流程使用的业务对象 Helpdesk.WorkOrder
User task 等待人完成的活动任务 ApproveCost
Outcome 任务完成选择的结果 Approve / Reject
Multi-user task 聚合多人的参与结果 第 17 章三人多数决
Due date / Timer 截止信息 / 实际计时活动 到期显示与超时路径不同

11.12 配合兼容的 Workflow Commons 4.x。实际活动任务与已结束任务、模块视图实体用途不同，任务完成动作要拿到正确的活动任务。接线详见第 10 章。

🗂️ 四、工单核心模型速查

实体或成员 教程归属 保存或修改规则
WorkOrder.Title / Description / EstimatedCost 核心字段 提交人仅编辑自己的草稿
WorkOrder.Status / Submitter / Assignee 状态与身份 受控服务端逻辑修改
WorkOrder_Department 工单到部门 多工单可属于同部门
WorkOrder_Submitter / WorkOrder_Assignee 工单到 System.User 实际账号可为 Administration.Account
WorkOrderLog 成功业务动作记录 与操作一致，不让客户端伪造
WorkOrderAttachment / WorkOrderPhoto 第 13 章加入 访问范围跟随工单
IntegrationJob 第 19 章可选 持久状态追踪后台工作
OfflineNote 第 21 章可选 设备笔记同步后再转草稿
AISuggestion 第 22 章可选 临时建议，经校验与确认才采用

费用边界为 大于 500 才审批。Draft 是草稿，Submitted 是待接单，AwaitingApproval 是待审批，InProgress 是维修中，Closed 是维修结束，Rejected 是审批拒绝。

🌐 五、集成与交付

JSON structure 描述消息形状，Import mapping 将外部字段变成对象，Export mapping 将对象变成外发消息。HTTP 200 仍需校验数据；超时不证明对方没有执行。

Task Queue 让任务在后台运行，Scheduled event 按时间触发；二者都要考虑失败与重复。Idempotency（幂等）意味着同一业务请求重复处理不会重复产生预期外的副作用，不等于“页面按钮只点一次”。

.mpr 用于项目模型，.mpk 可用于模块或应用包等分发用途，.mda 是部署包。只有部署包没有数据库与文件备份，不能恢复完整业务状态。

✅ 检查点

  1. WorkOrder 是流程实例吗？
  2. ACT 前缀是否自动保护权限？
查看答案
  1. 不是，它是本例的业务上下文对象。
  2. 不会，名称只是约定，权限和服务端校验必须配置。
