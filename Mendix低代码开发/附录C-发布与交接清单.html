附录 C · 发布与交接清单

⏱ 阅读约 6 分钟 ｜ Studio Pro 11.12 LTS，动手时间另计

🎯 一句话

每项交付结论都要对应一个版本、一条证据和一个负责入口。 这张清单用来整理材料，不会自动部署应用。

填写状态只使用“通过、失败、未测、不适用”；不适用要写原因。网页的完成按钮只保存读者进度，不能替代下列表格中的实际记录。

📦 一、版本与依赖

核验项 交接时填什么 完成条件
Studio Pro 11.12 的准确补丁号 团队和构建环境一致
源版本 分支、提交、变更说明 能找到产生部署包的源
部署包 名称、版本、构建时间 与验收版本相同
Marketplace 模块 名称、版本、依赖 在干净环境核验兼容
自有扩展 Java/JS、第三方库与维护人 代码、许可和构建说明可查
已知问题 问题、影响、负责人、复验入口 无掩盖的上线阻断项

Workflow Commons 使用兼容 11.12 的 4.x，升级时记录页面与角色变化。涉及旧实例、离线设备或模块更新时，附对应版本说明与演练证据。

🔐 二、账号、配置与数据

核验项 证据 未完成时的处理
独立角色测试 提交人、处理人、主管、管理员记录 不以管理员成功替代
数据与附件隔离 越权读取及下载测试 修复权限再测
密钥配置 配置项名称与保管入口，不填密钥本身 通过环境管理补齐
演示账号 正式环境停用或清除的记录 不交给真实用户使用
模板与初始化 Excel 模板、必要基础数据、执行人 新环境逐项初始化
外部地址 测试/生产目标与连接验证 不保留本机回环地址

密钥不写入本清单、源码、截图或故障日志。初始化和配置步骤必须说明在哪个环境执行，防止测试工具触发真实业务。

✅ 三、业务与失败场景

核验项 要保存的结果
费用边界 0、500、501 三条路径
人工任务 同意与拒绝，实际任务与业务状态一致
维修闭环 接单归属、非空处理结果、关闭记录
输入失败 空标题、负费用、缺部门
集成失败 404、503、坏结构、超时与断连
文件与导入 空内容、超大文件、重复行、再次确认
并发 真正同时提交和接单的实测，不只双窗口顺序操作
可选专题 已启用的多级审批、后台、离线或 AI 专项结果

每条保留输入、账号、预期、实际、时间和版本。失败先记录，修复后复跑；不要删除失败记录后仅留下最好的一次。

💾 四、发布与恢复

发布记录包含目标环境、发布时间窗、发布人、部署包、发布前备份和回退触发条件。确认测试通过的同一包进入目标环境，配置差异有记录。

恢复材料包含数据库与文件备份、匹配模型、恢复环境、操作步骤、实际耗时、恢复后的工单和附件核验。业务可接受的数据损失与恢复时间，应与演练结果对照。

旧包回退不能自动恢复数据，也不能撤销已经发送的外部操作。涉及数据迁移时附迁移与回退方案；无演练条件就标未测，不能宣称已经具备生产恢复能力。

🤝 五、交给下一位维护者

同伴的问题 交接入口
怎样运行和登录测试？ 环境说明与受控测试账号入口
哪个流程更新工单状态？ ACT/SUB 清单与 Workflow 定义
接口失败从哪里查？ 日志节点、追踪标识和任务状态页
谁能处理流程冲突？ 管理入口、职责与恢复记录
升级之前要测什么？ 本页清单与毕业项目 T01—T09
遇到未知问题怎么办？ 最后正常版本、负责人和问题记录位置

最后让同伴独立完成一次“打开工单、追到审批历史、找到对应日志”的演练。若仍需你口头提示路径，把它补入交接材料。

✅ 检查点

  1. 清单里能填写实际 API 密钥吗？
  2. 没有恢复演练能勾成通过吗？
查看答案
  1. 不能，填写配置名称与保管入口即可。
  2. 不能，应标未测并记录下一步。
