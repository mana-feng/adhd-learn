12 · 用 REST 连接外部系统

⏱ 阅读约 13 分钟 ｜ Studio Pro 11.12 LTS，动手时间另计

🎯 一句话

先把外部返回值变成可检查的临时对象，再决定是否写入业务数据。 本章为工单查询设备保修信息，查不到时仍能正常报修。

起点：在线应用和受权限控制的工单详情页。本章增加 HelpdeskIntegration 模块承载接口材料；不改变既有 WorkOrder 的身份、状态和费用权限。

🧩 一、用一个固定案例理解请求与响应

设备编号 A100 的服务返回设备名“会议室投影仪”、underWarranty=true。页面显示“保修内，请先联系供应商”；这只是建议，不自动把 EstimatedCost 改为 0。

契约项目 教学约定
方法与路径 GET，固定服务地址下的 /assets/A100
成功响应 HTTP 200，JSON 对象含 assetCode、name、underWarranty
找不到 HTTP 404
临时不可用 HTTP 503
结构错误 HTTP 200，但 underWarranty 返回对象而非 Boolean

HTTP 状态回答“这次请求怎样了”；JSON 字段回答“设备是什么”。200 不保证内容符合你的应用约束。接口由服务端调用，浏览器跨域设置不是这次服务端请求的主要检查位置。

🧪 二、启动本机练习服务

本章附带设备查询练习服务。它只监听本机，只返回虚构设备，不需要密钥。先安装 Python 3，把文件下载为 asset-service.py，在该文件所在目录打开终端运行：

python asset-service.py

终端保持打开，浏览器访问 A100 测试响应。把浏览器显示的完整 JSON 保存成测试样例，供下一步粘贴。A404、A503、ABAD 分别触发表中三种失败情形；其他未知编号返回 404。结束练习按 Ctrl+C。

这套地址只适用于 Studio Pro 和 Python 运行在同一台机器。部署到云以后，127.0.0.1 指向云中应用所在环境，需要换成真正可达的服务地址。

🛠️ 三、把 JSON 映射到临时对象

在 HelpdeskIntegration 新建 JSON structure JS_AssetResponse，粘贴成功响应样例，选择外层对象及三个字段。再新建 Import mapping IM_AssetResponse，选择该结构。

创建 非持久化实体 AssetResponse，字段 assetCode String、name String、underWarranty Boolean；映射各 JSON 字段到对应属性，根节点创建一个新对象。名字大小写对照样例，不把下划线和驼峰当成同一种字段名。

建立页面 AssetResponse_View，参数 AssetResponse，只读显示设备编号、名称及保修状态。为需要查询的业务角色映射 Integration 模块角色 Reader，授予该非持久化实体与页面所需访问权限。映射成功后仍检查返回编号是否为 A100、名称是否为空；这种检查属于你的业务契约。

🛠️ 四、配置一次完整调用

在 HelpdeskIntegration 新建 ACT_Asset_LookupDemo，允许 Reader 调用；先用固定 A100 做不关联真实工单的演示。

Call REST service 项目 本次填写
Location http://127.0.0.1:8766/assets/A100，固定模板
HTTP method GET
Use timeout on request Yes
Timeout (s) 5，教学试验值
HTTP headers Accept 的值为 application/json
Response handling Apply import mapping
Mapping / 输出对象 IM_AssetResponse / AssetResponse

GET 这次没有请求体。成功路径核验对象和必需字段，再 Show page AssetResponse_View。出错路径返回“设备信息暂不可用，可以继续填写工单”，并写一条不含完整响应体的错误日志。

在调用动作上配置 Custom with rollback 错误处理，错误路径不要再使用失败映射的输出对象。若需要识别 404/503，先判断当前可用 HTTP 响应对象是否为空，再读取状态；连接失败或超时可能没有 HTTP 响应。$latestHttpResponse 的作用域与响应体选项见官方 REST 动作说明。

中途停靠： 能显示 A100 的三项信息，也能在 A503 时看到可理解的错误，就完成了首次集成。之后再将入口放进工单详情。

🔐 五、接入工单前补上边界

新增 WorkOrder.AssetCode（String 40），Requester 仅能在自己的 Draft 中修改，与第 08 章规则合并。建立 Helpdesk 的包装 Microflow ACT_WorkOrder_LookupAsset：参数 WorkOrder，服务端按 ID 重新读取并检查当前用户可读，再校验 AssetCode 仅由允许的字母与数字组成、长度合规，最后调用内部查询。

把基础地址设成服务端常量 HelpdeskIntegration.AssetApiBaseUrl，客户端不能覆盖。外部鉴权值也只在服务端配置；真实服务使用 HTTPS，不把令牌写进 Nanoflow、页面或示例截图。固定可信主机，业务参数只决定设备编号，不接受用户输入任意完整 URL。

本例只查询，不改变 WorkOrder。以后要创建外部采购单时，需要考虑：外部已创建，但本地等待超时怎么办？本地事务回滚不能撤销对方系统的动作；应使用对方支持的幂等键与查询核对，再决定重试。后台做法见第 19 章。

🔎 六、验收不能只用成功响应

依次把教学入口中的编号换成 A404、A503、ABAD；再停止 Python 服务重试。记录“HTTP 失败”“响应结构失败”“无连接”各自的日志与页面结果。每轮结束检查原工单状态、费用与审批实例数量没有被查询动作改变。

最后恢复 A100。如果错误分支正常但成功页再也打不开，先检查你是否忘了恢复地址或错误处理把成功路径也接到了失败出口。

✅ 检查点

  1. 返回 200 就可以写入工单了吗？
  2. 云上能继续用 127.0.0.1:8766 吗？
  3. 超时是否证明外部动作没执行？
  4. 连接失败时可以直接读 HTTP 状态吗？
查看答案
  1. 还要检查映射和业务字段，本章查询结果仅供查看。
  2. 不能连接你电脑上的练习服务，需要替换为云端可达且可信的地址。
  3. 不证明。写操作要用幂等和状态核对处理不确定结果。
  4. 不可以先假定响应对象存在，应检查是否为空。
