13 · 附件、图片与导入导出

⏱ 阅读约 12 分钟 ｜ Studio Pro 11.12 LTS，动手时间另计

🎯 一句话

文件需要归属和权限，表格数据需要先校验再进入业务实体。 本章让小林上传故障照片，并让管理员预览部门导入错误。

起点是具有 WorkOrder、Department 和四类角色的在线应用。附件是主线操作；Excel 部分先用部门做独立练习，不直接批量创建工单或触发审批。

🧩 一、文件对象与文件内容分别检查

创建持久化实体 WorkOrderAttachment，Generalization 选择 System.FileDocument。继承获得 Name、HasContents 等成员，再增加 Attachment_Order 到 WorkOrder 的单值关联：每个附件属于一张工单，一张工单有多个附件。

如果需要原生图片展示，另建 WorkOrderPhoto 继承 System.Image，关联 Photo_Order。System.Image 本身继承 FileDocument；不要把文件内容存进 WorkOrder 的长字符串，也不要让一个实体同时继承两个父类。

对象 负责什么 检查重点
WorkOrder 工单状态、提交人与处理人 当前人能否读这张工单
WorkOrderAttachment 文件元数据与内容 附件权限是否限制到可读工单
WorkOrderPhoto 图片与工单关联 展示和原文件下载均需权限

工单删除规则暂设为“有关联附件时阻止删除”，与保留历史的策略一致。测试清理使用专用草稿，不删除真实审批记录。

🛠️ 二、建立有归属的上传与下载入口

  1. 建立 WorkOrderAttachment_Edit 页面，参数 WorkOrderAttachment。Data view 中加入 File manager，上下文就是这个文件对象。
  2. 控件选择上传用途，Max file size 设 5 MB，Allowed extensions 设 jpg;jpeg;png;pdf，作为本练习白名单。
  3. 建立 ACT_Attachment_New，参数 WorkOrder。服务端重新检查当前人为提交人且状态 Draft；创建附件、设置 Attachment_Order，提交元数据后打开上传页。
  4. 上传完成后保存并返回附件列表。下载按钮对当前附件执行下载，所需读取范围跟随工单权限。

为 Requester 设置附件读取范围为自己工单；写范围进一步限制为自己的 Draft。上传所需的继承成员权限按控件一致性检查补齐，Attachment_Order 只由服务端设置。其他角色沿用各自的工单可读范围，禁止客户端随意创建、删除或改挂附件。

用户可以取消上传，因此有元数据不代表 HasContents 为 true。列表可以提示“尚未上传”，清理空文件前先确认它不再被编辑。附件创建失败或上传失败都不应该改变工单状态。

扩展名白名单不会验证文件真实内容。控件限制见File Manager 文档。正式接收外部文件时可加入隔离、真实类型检查与扫描，扫描前不对其他用户开放下载。本练习使用自己制作的无敏感文件。

🖼️ 三、图片展示从正确上下文开始

照片上传页的 Data view 使用 WorkOrderPhoto，选择适配 System.Image 的上传控件；工单详情中的图片列表通过 Photo_Order 关联获取。每个列表项再绑定一个图片对象，不把整个列表传给单对象控件。

准备横图和竖图，手机上检查比例、原图入口和可达的关闭按钮。图片空白时依次查对象、HasContents、实际文件类型与读取权限，先不要改样式。

中途停靠： 小林能下载自己的图片，小王无法下载小林的图片，就完成附件主线。

📥 四、Excel 先进入暂存区

安装兼容 Studio Pro 11.12 的 Excel Importer 与 Excel Exporter，记录准确版本。按对应版本说明补齐依赖，包括 Importer 使用的 Mx Model Reflection 与 Community Commons。模板和反射配置只开放给管理员。Importer 说明

给 Department 增加 Code（String20），管理员先把行政部设为 ADM，并检查已有数据的 Code 唯一。新增 DepartmentImportRow 暂存实体：Code String20、Name String80、ErrorMessage String无限制，只允许管理员访问。

在自己的表格编辑器建立工作簿，第一个工作表首行是 Code、Name。按照下表填四行，第三列只是教学说明，不放进文件：

Code Name 测试目的
ADM 行政部 已有同码同名，应跳过
RD 研发部 与下一行重复
RD 研发二部 同批重复，不允许自动选一个
留空 财务部 Code 单元格真正留空，不输入“留空”

打开模块模板管理页，刷新反射中的实体信息，建立映射：Sheet Nr 1、Header Row Nr 1、Import from Row Nr 2，Code 和 Name 映射到暂存实体。逐列核对类型和列位置。

自建管理员上传入口，调用该版本提供的导入动作，参数以已安装动作的签名为准。先让四行出现在预览页，Department 数量仍然不变。为了让本例不依赖多批次管理，练习时只允许一名管理员操作，开始新批前清理上个已结束批次的暂存行；生产需增加批次实体、归属与并发隔离。

🛠️ 五、验证、纠正、确认分开执行

ACT_DepartmentImport_Validate 遍历暂存行，trim 后检查 Code、Name 非空，再按 Code 检查同批重复。重复组的每一行均写 ErrorMessage，不能靠“第一行赢”选择名称。已有 Code 同名跳过，已有 Code 异名报需人工确认。

预览预期：RD 两行均报重复、空 Code 行报必填、ADM 标记跳过。整批存在错误就不能确认，页面禁用确认按钮，确认 Microflow 也重新检查。先校验所有行，再执行创建，不要一边检查一边写正式部门。

删除第二个 RD，给财务部补 FIN，重新导入新批次。此时预期跳过 1 行、新建 2 个部门。确认动作对这个小批次在一个事务中检查并创建；再次确认不会新增同码部门。顺序查重没有证明多管理员同时导入安全，生产还需唯一性与并发冲突处理。

不要让 Excel 直接写 WorkOrder.Status、Submitter 或 Assignee：这些字段属于受控业务操作的结果。批量导入工单需要复用服务端身份和状态规则。

📤 六、导出仍受数据权限约束

Exporter 使用独立模板和导出动作。先导出 Department.Code 与 Name 两列，生成文件后交给 Download file；不要认为导入模板可以直接当导出模板。Exporter 说明

扩展工单导出时，服务端按当前用户可读范围 Retrieve，不只相信浏览器传入的 ID。把用户输入当文本写入单元格；对以等号等字符开头的标题验证不会变成公式。若所选版本提供公式转文本选项，启用并测试。

验收包含空文件、超大文件、错误列名、重复确认和越权下载。文件能打开只是第一步，还要核对行数、字段、数据归属。

✅ 检查点

  1. HasContents=false 说明什么？
  2. 为什么关联只允许服务端设置？
  3. 两条 RD 谁应该赢？
  4. 导出为何重新按权限查询？
查看答案
  1. 元数据可能存在，但还没有文件内容。
  2. 避免客户端把附件改挂到另一人的工单。
  3. 两行都标记重复，管理员纠正后再确认。
  4. 浏览器传入 ID 不能作为可读授权的依据。
